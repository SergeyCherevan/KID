# 🧭 Работа в KID

- Обзор продукта: [README.md](README.md). Карта разработки и правила
  актуальности: [harness/README.md](harness/README.md).
- Перед изменением читайте соответствующие решения и API в harness/context.
  Планы, контракты и аудиты находятся в harness/work; проверки — в harness/checks.
- Сохраняйте поведение production-кода, публичный API, имена сборок и границы
  доступа при структурных переносах. Внешние probes остаются вне solution.
- Общий запуск: `./harness/tools/Invoke-Harness.ps1`; полный автоматический
  набор: `-Command check -Profile Full` (открывает WPF-окна).
- Ведите статус, чекбоксы, фактические проверки и открытые вопросы в плане.
  Не заменяйте текущую приёмку историческими результатами.
- Генерируемые результаты сохраняйте в gitignored artifacts/harness или bin/obj.
  Не меняйте пользовательские настройки ради проверки миграции.
- Для этой работы используйте файловые и shell-инструменты без Computer Use.
  Коммиты — локальные, английские Conventional Commits; push только по запросу.
- В ответах используйте эмодзи для структуры. Завершайте ответ 3–4 возможными
  продолжениями, отделёнными горизонтальным разделителем и заголовком
  `## 🔭 Возможные продолжения`; каждый пункт настоящего нумерованного списка
  начинается с эмодзи.
