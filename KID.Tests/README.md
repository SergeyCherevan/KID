# KID.Tests

## Запуск и структура

Из корня репозитория:

```powershell
dotnet build KID.sln -c Release
dotnet test KID.Tests/KID.Tests.csproj -c Release --no-build
```

Структура production-кода описана в [CodeExecution](../docs/CodeExecution.md). Тестовые каталоги группируют сценарии: `Compiler/`, `Execution/`, `Console/` и `Lifecycle/`. Импорты используют пространства имён соответствующих частей и их подпапок `Interfaces/`.

`CompiledProgram_ConsoleClear_UsesConsoleContextBridge` проверяет полный путь от компиляции `System.Console.Clear()` до очистки WPF TextBox и вывода следующего текста. Эта проверка защищает строковое полное имя консольного bridge от ошибок при переносе классов.

## Условия выполнения

`KID.Tests` — проект автоматизированных тестов для работ по надёжному выполнению пользовательского кода внутри процесса IDE в рамках C2/C3.

Обычный запуск тестов должен оставаться детерминированным: он не должен открывать видимые окна, обращаться к сети или использовать реальное аудиоустройство. WPF-контролы создаются с помощью `StaTest` в отдельном STA-потоке. Для проверки аудио и жизненного цикла выполнения используются тестовые заглушки, пока на следующих этапах плана в production-коде не появятся соответствующие точки подмены зависимостей.

Тесты, отмеченные как пропущенные, служат исполняемыми спецификациями поведения, которое будет реализовано на следующих этапах `.codex/plans/C2_C3_IN_PROCESS_EXECUTION_RELIABILITY.plan.md`. В причине пропуска каждого такого теста указан этап, после которого тест должен быть включён. Проходящие characterization-тесты фиксируют уже существующие гарантии, которые нельзя потерять при рефакторинге.
