# D001. Общая концепция .KID

## Статус

Решение принято. Документ согласован автором проекта.

## Контекст и задачи

.KID разрабатывается как новый инструмент для изучения программирования.

Перед проектом стояли следующие задачи:

- **Обеспечить простой старт.** Ученик должен иметь возможность начать с небольшой процедурной программы в одном скрипте, без предварительного освоения структуры проекта, объявления класса, метода `Main` и создания собственного окна.
- **Дать непосредственный результат.** Работа с консолью и графикой должна быть доступна с первых занятий через простые команды. Результат выполнения должен быть виден рядом с кодом.
- **Поддержать дальнейший рост.** Среда должна позволять переходить от первых последовательностей команд к объектно-ориентированному программированию и более сложным учебным проектам, подготавливая ученика к профессиональной разработке.
- **Сохранить широкие возможности языка и платформы.** По мере обучения ученику должны быть доступны в том числе работа с файлами и сетью.

Общая концепция была первоначальным замыслом проекта. Решение об отказе от ограничительной песочницы было принято при рассмотрении возможностей, которые ученик потерял бы при таком подходе.

## Выбор подхода

При поиске способа решить поставленные задачи внимание привлёк подход BASIC-256:

- редактор, текстовый вывод и графическое поле объединены в одной среде;
- программа запускается одной кнопкой;
- первые программы состоят из простой последовательности команд;
- графические операции доступны непосредственно, без создания собственного графического приложения;
- одна программа может совместно использовать текстовый и графический вывод.

Эти принципы соответствовали желаемому начальному учебному опыту и были выбраны как основа организации работы в .KID.

Исходным выбором языка для .KID был C#. Причиной стали его популярность и широкое практическое применение: от серверной разработки на ASP.NET Core и настольных приложений на WPF, WinUI 3 и Avalonia до мобильных приложений на MAUI и игр на Unity.

Отдельное сравнение альтернативных языков в рамках обсуждения этого решения не зафиксировано.

## Принятое решение

Создать учебную среду на C# и .NET, которая использует принципы организации учебной работы BASIC-256 и предоставляет мост от простой процедурной программы в одном скрипте к объектно-ориентированному программированию, более сложным учебным проектам и профессиональной разработке.

### Начальная учебная программа

Ученик начинает с одного скрипта, содержащего последовательность команд. Для первых программ ему не требуется самостоятельно объявлять класс, метод `Main` или создавать окно приложения.

Среда предоставляет редактор кода, текстовый ввод и вывод, графическое поле и запуск программы одной кнопкой.

Основной цикл работы: написать команды, запустить программу и увидеть результат рядом с кодом.

### Работа с графикой и консолью

Ученик получает упрощённый API для непосредственной работы с графикой: выбора цвета, рисования фигур, вывода текста и других операций.

Например, рисование круга выражается вызовом `Graphics.Circle(...)`, без предварительного создания собственного графического приложения. Текстовый вывод доступен через привычные средства C#, например `Console.WriteLine(...)`.

Оба способа вывода можно использовать в одной программе.

### Дальнейшее обучение

Простота первых программ сочетается с возможностью постепенно осваивать C# и .NET.

Предполагаемый путь ученика:

1. Простая процедурная программа в одном скрипте.
2. Освоение возможностей языка, включая объектно-ориентированное программирование.
3. Более сложные учебные проекты.
4. Переход к профессиональной разработке на C# и .NET.

Этот путь выражает образовательную цель проекта. Он не означает, что .KID должен полностью заменить профессиональные инструменты разработки.

### Доступ к C# и .NET

Пользовательский код не помещается в ограничительную защитную песочницу, специально сужающую доступные ученику возможности платформы.

Общий принцип — предоставить полный или почти полный доступ к C# и .NET, ориентируясь на возможности, доступные при запуске обычных программ из Visual Studio.

Точная степень этого доступа и его технические границы относятся к решению `D008`.

## Рассмотренный альтернативный подход

Рассматривалось выполнение пользовательского кода в ограничительной песочнице, в том числе достаточно свободной.

При оценке такого подхода обнаружилось множество возможностей, которые стали бы недоступны ученику или потребовали бы дополнительных механизмов доступа, как например:

- **Работа с файлами** — для освоения основ разработки программного обеспечения.
- **Работа с сетью** — например, для создания простых сетевых игр.
- и другие.

По оценке автора проекта, рассмотренные варианты предоставления таких возможностей в рамках песочницы были крайне громоздкими и неудобными.

В результате был выбран широкий доступ к возможностям C# и .NET без ограничительной песочницы.

## Последствия и границы решения

- Первые программы строятся вокруг последовательности команд и непосредственного результата в текстовом и графическом выводе.
- C# используется с самого начала обучения и остаётся применимым при переходе к более сложным задачам.
- Работа с файлами и сетью входит в предполагаемые учебные возможности среды.
- Ограничительная песочница не используется как средство защиты от пользовательского кода. Поэтому из данного решения не следует гарантия безопасного выполнения недоверенных программ.
- Преемственность с BASIC-256 относится к принципам организации учебной работы. Совместимость языков, API или поведения программ этим решением не устанавливается.
- Документ фиксирует общую концепцию. Детали выполнения пользовательского кода и точные границы доступности C# и .NET рассматриваются отдельно, в том числе в `D008`.

Предоставленный автором скриншот иллюстрирует сходную организацию BASIC-256 и .KID: редактор слева, текстовый вывод и графическое поле справа. Примеры программ показывают совместный вывод текста и рисование фигур. Автор подтвердил, что эти принципы были частью замысла .KID.
