# 📦 D005. Выделение KID.Library в отдельный проект

## 🎯 Контекст и задача

Учебный API .KID должен быть доступен за пределами самой IDE. Ученику необходимо сохранить возможность пользоваться библиотекой при переходе к разработке собственной C#-программы в Visual Studio, Rider или другой среде.

Предполагаемый сценарий: подключить `KID.Library` к своей программе, предоставить собственный WPF `Canvas` для `Graphics` и использовать знакомые команды рисования.

## ✅ Решение и причины выбора

Выделить `KID.Library` в отдельный проект решения, независимый от проекта `KID.WPF.IDE`. IDE использует библиотеку; библиотека не должна требовать подключения IDE.

**Первоначальная причина выделения — самостоятельное использование библиотеки.** Учебный API не должен быть доступен исключительно внутри .KID IDE. Такое разделение позволяет ученику продолжать использовать знакомые средства в собственном приложении, постепенно переходя к самостоятельной организации программы и её окна.

Отсутствие зависимости от IDE закрепляет архитектурную границу между библиотекой и приложением, которое её использует.

Конкретные рассмотренные альтернативы и причины отказа от них не зафиксированы.

## 🔭 Возможное будущее развитие

Позднее появилось возможное применение этого разделения: запускать программы из .KID IDE в отдельном процессе, с собственными окнами приложения и консоли — **App-Window & Console**, с возможностью произвольно назначать и переназначать разные целевые `Graphics.Canvas` для рисования.

Это направление будущего развития, а не первоначальная причина выделения библиотеки и не утверждение о наличии такой функции сейчас.

## 📌 Последствия и границы

- Библиотека и IDE образуют отдельные проекты с направлением зависимости `KID.WPF.IDE → KID.Library`.
- Самостоятельное использование библиотеки является целью решения; готовность соответствующего публичного API требует отдельной оценки.
- Независимость от IDE не означает независимость от WPF и Windows: текущая графическая реализация использует WPF `Canvas`.

## 🔬 Проверка текущей реализации

Проверено 2026-11-01 чтением кода: разделение проектов реализовано, однако сценарий подключения собственного холста через публичный API сейчас ограничен.

- [KID.Library.csproj](../../../KID.Library/KID.Library.csproj) не содержит ссылки на IDE; [KID.WPF.IDE.csproj](../../../KID.WPF.IDE/KID.WPF.IDE.csproj) ссылается на библиотеку. Библиотека нацелена на `net10.0-windows` и использует WPF.
- В [Graphics.System.cs](../../../KID.Library/Graphics/Graphics.System.cs) метод `Graphics.Init` имеет доступ `internal`, а свойство `Graphics.Canvas` — закрытый setter. Доступ IDE к внутренним членам предоставлен через `InternalsVisibleTo` в [AssemblyInfo.cs](../../../KID.Library/Properties/AssemblyInfo.cs).
- [Graphics.CanvasSize.cs](../../../KID.Library/Graphics/Graphics.CanvasSize.cs) содержит привязку к именам элементов разметки IDE. Поэтому отсутствие ссылки на проект IDE не означает полного отсутствия предположений о её устройстве.

Тесты и запуск отдельного приложения с библиотекой не проводились. Образовательная цель и будущее выполнение в отдельном процессе этой проверкой не подтверждались.
