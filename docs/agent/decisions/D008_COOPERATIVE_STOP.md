# 🛑 D008. Кооперативная остановка и инструментирование пользовательского кода

## 🎯 Контекст и задача

Пользователь должен иметь возможность остановить свою программу кнопкой STOP, сохраняя работоспособность IDE.

Согласно D007, в базовом сценарии программа выполняется внутри процесса IDE. В таких условиях нельзя надёжно принудительно завершить произвольный пользовательский код, сохранив корректную работу общего процесса. Поэтому остановка требует участия выполняемого кода.

Ученик может писать обычную программу без обязательного добавления проверок STOP и обработки отмены: это обеспечивает среда. При необходимости он может самостоятельно добавлять проверки и использовать механизмы отмены.

## ✅ Решение и причины выбора

Использовать **кооперативную остановку с автоматическим инструментированием пользовательского кода**: перед компиляцией преобразовывать его синтаксическое дерево, добавляя проверки запроса STOP.

При нажатии STOP среда запрашивает отмену текущего запуска. Выполнение реагирует на неё при достижении добавленной проверки либо операции, поддерживающей отмену.

Кооперативная остановка является следствием выбранного в D007 выполнения внутри процесса IDE. Автоматическое добавление проверок позволяет сохранить простой учебный сценарий: организацию остановки берёт на себя среда.

## ⚖️ Рассмотренная альтернатива

Рассматривалось выполнение пользовательских программ **в отдельном процессе по умолчанию**.

Причины выбора общего процесса описаны в D005–D007: самостоятельная `KID.Library` работает с предоставленными IDE консолью и холстом через обычные вызовы и ссылки на объекты. Такой подход сохраняет линейную форму учебной программы и не требует межпроцессного протокола передачи графических команд и результатов.

Отдельный процесс предусмотрен для будущего сценария App-Window, но не выбран как базовый способ запуска.

## 📌 Последствия и границы

- Остановка зависит от достижения проверок STOP или поддержки отмены выполняемой операцией; мгновенное завершение произвольного кода не гарантируется.
- Среда отвечает за преобразование программы и корректность добавляемых проверок.
- Многопоточность, асинхронность и блокирующие синхронные операции требуют дополнительной обработки. Принятое решение само по себе не обеспечивает корректного поведения всех таких сценариев.

## 🔭 Будущее развитие

Планируется устранить некорректное поведение при выполнении пользовательского кода, в том числе связанное с многопоточностью, асинхронностью и блокирующими синхронными операциями.

Возможно ограничение некоторых конструкций для программ, выполняемых внутри общего процесса IDE. Программы с такими конструкциями предполагается запускать из IDE только в собственном окне и отдельном процессе.

Возможные ограничения определяют границы доступа к C# и .NET в конкретном сценарии — при выполнении пользовательской программы внутри процесса IDE. Таким образом, доступные возможности могут зависеть от выбранного сценария запуска. Это связывает D008 с принципом широкого доступа к C# и .NET из D001.

Конкретные ограничения пока не определены; их введение остаётся возможным вариантом развития.

## 🔬 Проверка текущей реализации

Проверено 2026-11-01, HEAD `d6926c2`, чтением кода и существующих тестов: основной механизм реализован.

- [CSharpCompiler.cs](../../../KID.WPF.IDE/Services/CodeExecution/Compilation/CSharpCompiler.cs) применяет [CancellationInstrumentationRewriter.cs](../../../KID.WPF.IDE/Services/CodeExecution/Compilation/Rewriters/CancellationInstrumentationRewriter.cs), добавляющий проверки STOP в поддерживаемые конструкции. Для некоторых вызовов `Thread.Sleep` и `Task.Delay` предусмотрены преобразования с поддержкой отмены.
- [ExecutionSession.cs](../../../KID.WPF.IDE/Services/CodeExecution/ExecutionSession.cs) отменяет токен сессии по запросу STOP; [StopManager.cs](../../../KID.Library/ExecutionEnvironment/StopManager.cs) предоставляет проверку отмены, используемую инструментированным кодом.

Тесты и интерактивная проверка в этой сессии не запускались. Проверка подтверждает наличие механизма, но не полноту поддержки произвольных многопоточных, асинхронных и блокирующих программ.
