# 🪟 D011. Взаимодействие главного окна WPF с WinAPI

## 🎯 Контекст и задача

Главное окно .KID использует собственное оформление заголовка и рамки вместо стандартного оформления Windows.

Для такого окна потребовалась дополнительная настройка поведения и внешнего вида: корректировка размеров и положения при разворачивании с учётом рабочей области монитора, устранение зазоров по краям и применение прямоугольной области окна для отключения системного скругления углов.

Необходимо разграничить пользовательские команды и состояние окна, работу с конкретным WPF-окном и его нативную настройку через WinAPI.

## ✅ Решение и причины выбора

Сосредоточить нативную настройку главного окна в `MainWindowWinAPIInteropService`, доступном через интерфейс `IMainWindowWinAPIInteropService`.

Причина такого разделения — отделить нативную настройку окна от пользовательских команд и кода подключения конкретного окна. `MainViewModel` отвечает за состояние и команды, `MainWindow` связывает компоненты с WPF-окном и его жизненным циклом, а `MainWindowWinAPIInteropService` сосредоточивает взаимодействие с WinAPI.

### 🧠 MainViewModel — состояние и пользовательские команды

`MainViewModel`:

- хранит `WindowState` и предоставляет команды сворачивания, разворачивания и восстановления;
- обновляет обозначение кнопки разворачивания;
- запрашивает перемещение через событие `RequestDragMove`;
- инициирует закрытие через интерфейс `IClosable`.

ViewModel не получает дескриптор окна и не обрабатывает WinAPI-сообщения. При этом она связана с WPF через тип `WindowState`.

### 🪟 MainWindow — связь с конкретным окном

`MainWindow` связывает состояние и команды ViewModel с WPF:

- двусторонняя привязка синхронизирует `WindowState`;
- запрос перемещения обрабатывается вызовом `DragMove`;
- реализация `IClosable` связывает команду закрытия с окном, которое организует процедуру завершения работы.

Окно также получает нативный дескриптор, подключает interop-сервис после `SourceInitialized` и уведомляет его об изменениях размера.

### ⚙️ MainWindowWinAPIInteropService — нативная настройка

Сервис подключает обработчик оконных сообщений, обрабатывает `WM_GETMINMAXINFO` и рассчитывает параметры разворачивания по рабочей области монитора с поправками для компенсации рамки.

Через `SetWindowRgn` он применяет прямоугольную область окна и обновляет её при изменении размера.

Прямой зависимости между `MainViewModel` и interop-сервисом нет. Например, разворачивание проходит по следующей цепочке:

`MaximizeCommand` → изменение `MainViewModel.WindowState` → привязка к `MainWindow.WindowState` → обработка нативного сообщения interop-сервисом.

## 📌 Последствия и границы

- Пользовательские команды, подключение к жизненному циклу окна и нативные операции имеют отдельные области ответственности.
- Вызовы WinAPI, нативные структуры и обработка сообщений сосредоточены в interop-сервисе.
- Разделение остаётся внутри WPF-приложения: оно не делает управление окном независимым от Windows и WPF.
- Расчёт размеров использует фиксированные поправки для компенсации рамки. Корректность результата при произвольных настройках DPI, мониторов и панели задач требует отдельной проверки.
