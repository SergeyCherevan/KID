# Перенос каталогов шрифтов, размеров и тем из RESX в JSON

- **Статус:** `completed` — реализация, автоматические проверки и ручная приёмка завершены.
- **Дата:** 2026-10-26.
- **Ветка:** `feature/FontAndThemeJsonCatalogs`.
- **База исследования:** `develop`, коммит `3c6b989`.
- **Текущий результат:** оба каталога перенесены в JSON; Release-сборка и 277 профильных тестов прошли. Пользователь подтвердил успешную ручную UI-приёмку 2026-10-26.

## 1. Цель и границы

Заменить индексированные `Resources/AvailableFontsAndSizes.resx` и
`Resources/AvailableThemes.resx` встроенными JSON-каталогами по образцу
`Resources/AvailableLanguages.json`: явные массивы, порядок записей как порядок
меню, строгая проверка данных, неизменяемый снимок и диагностируемый fallback.

Сохранить существующие интерфейсы сервисов, состав каталогов, фильтрацию шрифтов
по наличию в Windows, ключи настроек и применение тем. Названия тем продолжат
храниться в `Strings*.resx`, XAML-словари — в `Themes/`.

В объём не входят новые шрифты/темы, пользовательские внешние каталоги,
горячая перезагрузка, миграция формата `settings.json`, переработка DI или
общая универсальная инфраструктура каталогов. `LanguageCatalog` используется
как образец; менять его для этой задачи не требуется.

## 2. Исходное состояние

### Шрифты и размеры

`KID.WPF.IDE/Services/Fonts/FontProviderService.cs` читает
`KID.Resources.AvailableFontsAndSizes` через `ResourceManager`:

- `Font_Count` и `Font_0`…`Font_8`: Consolas, Cascadia Code, Cascadia Mono,
  JetBrains Mono, Fira Code, Source Code Pro, Courier New, Lucida Console,
  Segoe UI Mono.
- `FontSize_Count` и `FontSize_0`…`FontSize_7`: 10, 11, 12, 13, 14, 16, 18, 20.
- При запросе шрифтов берётся пересечение с `Fonts.SystemFontFamilies`;
  сравнение названий и устранение дублей используют `OrdinalIgnoreCase`.
- Резерв шрифтов — `Consolas`, включая случай пустого пересечения;
  резерв размеров — перечисленные восемь значений.
- Ошибки чтения логируются с `DiagnosticEventIds.SettingsFallback`.

### Темы

`KID.WPF.IDE/Services/Themes/ThemeProviderService.cs` читает
`KID.Resources.AvailableThemes` через `ResourceManager` при создании сервиса:

- `Theme_Count` и пары `Theme_N_LocalizationKey` / `Theme_N_ResourcePath`.
- Порядок: VS2022 Light, VS2022 Dark, VS2026 Light, VS2026 Dark.
- Проверяет непустые поля и относительный путь с расширением `.xaml`,
  пропускает некорректные записи и повторяющиеся ключи.
- Ключи сравниваются через `Ordinal`; старые `Theme_Light` / `Theme_Dark`
  разрешаются в `Theme_VS2022Light` / `Theme_VS2022Dark`.
- Стартовая и резервная тема — `Theme_VS2022Light` с путём
  `Themes/VS2022LightTheme.xaml`.

`MenuViewModel` уже получает списки через `IFontProviderService` и
`IThemeProviderService`; источник данных скрыт за этими интерфейсами.
`ThemeService` применяет словарь, сохраняет канонический ключ и обрабатывает
ошибки загрузки XAML отдельно от чтения каталога.

### Существующий образец и связанные тесты

- `KID.WPF.IDE/Services/Localization/LanguageCatalog.cs` показывает строгую
  десериализацию `System.Text.Json`, `Lazy<T>`, неизменяемые данные и
  цельный резерв при ошибке.
- `KID.WPF.IDE/KID.WPF.IDE.csproj` явно встраивает языковой JSON через
  `EmbeddedResource` с фиксированным `LogicalName`.
- `KID.Tests/Localization/LanguageCatalogResourceTests.cs`, тест
  `EnglishFallbackAndOtherBaseResourcesAreInMainAssembly`, прямо читает старые
  ресурсы шрифтов и тем и их счётчики. При миграции его необходимо адаптировать.
- `KID.Tests/Themes/ThemeProviderServiceTests.cs` проверяет порядок тем,
  резерв, названия и совместимость ключей; `ThemeSwitchingTests.cs` проверяет
  работу настоящих словарей в WPF.

## 3. Целевой формат ресурсов

### `Resources/AvailableFontsAndSizes.json`

Один объект с двумя обязательными непустыми массивами. Размеры — JSON-числа,
не строки; десятичный разделитель при добавлении дробного размера — точка.

```json
{
  "fonts": [
    "Consolas",
    "Cascadia Code",
    "Cascadia Mono",
    "JetBrains Mono",
    "Fira Code",
    "Source Code Pro",
    "Courier New",
    "Lucida Console",
    "Segoe UI Mono"
  ],
  "fontSizes": [10, 11, 12, 13, 14, 16, 18, 20]
}
```

Логическое имя: `KID.Resources.AvailableFontsAndSizes.json`.

### `Resources/AvailableThemes.json`

Непустой массив объектов с двумя обязательными полями. `localizationKey`
сохраняет роль стабильного идентификатора темы и ключа её названия.

```json
[
  {
    "localizationKey": "Theme_VS2022Light",
    "resourcePath": "Themes/VS2022LightTheme.xaml"
  },
  {
    "localizationKey": "Theme_VS2022Dark",
    "resourcePath": "Themes/VS2022DarkTheme.xaml"
  },
  {
    "localizationKey": "Theme_VS2026Light",
    "resourcePath": "Themes/VS2026LightTheme.xaml"
  },
  {
    "localizationKey": "Theme_VS2026Dark",
    "resourcePath": "Themes/VS2026DarkTheme.xaml"
  }
]
```

Логическое имя: `KID.Resources.AvailableThemes.json`.

Оба файла встраиваются в основную сборку через `EmbeddedResource` и
исключаются из `None` аналогично языковому каталогу. Внешние копии рядом
с приложением не нужны; изменение каталога требует пересборки. Счётчики
и числовые индексы больше не используются.

## 4. Правила загрузки, проверки и резерва

### Общие правила

1. Ввести отдельные внутренние `FontCatalog` в `Services/Fonts/` и
   `ThemeCatalog` в `Services/Themes/`; для тем использовать существующую
   модель `KID.Models.ThemeDefinition`.
2. Читать поток через `Assembly.GetManifestResourceStream`; закрывать его
   после десериализации. Для тестирования предусмотреть внутреннюю точку
   загрузки с `Func<Stream?>`, без изменения публичных интерфейсов и DI.
3. Загружать и кэшировать снимок один раз на экземпляр сервиса через
   `Lazy<T>` с `ExecutionAndPublication`. Кэшировать также резервный результат.
4. Применять настройки JSON по образцу `LanguageCatalog`: точный регистр
   полей, запрет неизвестных и повторных свойств, комментариев и завершающих
   запятых. Отклонять неверную корневую структуру, отсутствующие обязательные
   поля, `null`, пустые коллекции и неверные типы значений.
5. Строки должны быть непустыми и не содержать пробелов по краям.
   Возвращать неизменяемые коллекции, сохраняя порядок JSON.
6. При ожидаемой ошибке чтения/десериализации/валидации отклонять весь
   соответствующий JSON-каталог и выдавать его цельный резерв. Для шрифтов
   и размеров это один общий каталог: ошибка любого массива включает оба
   резервных списка. Это намеренное отличие от прежнего частичного пропуска
   некорректных RESX-записей.
7. Предупреждать один раз при загрузке повреждённого каталога через
   существующий `SettingsFallback`: имя ресурса, причина, а для ошибки записи —
   индекс и поле. Не превращать любые программные ошибки в тихий fallback;
   набор перехватываемых исключений ограничить ожидаемыми ошибками загрузки.

### Специфика шрифтов и размеров

- Названия шрифтов уникальны по `OrdinalIgnoreCase`; дубли являются ошибкой
  каталога. Регистр и написание корректных имён сохраняются.
- Размеры уникальны, конечны (`double.IsFinite`) и больше нуля. JSON-строки
  с числами, переполнение `double`, нули и отрицательные значения отклоняются.
  Не вводить дополнительных диапазонов и автоматической сортировки.
- Отсутствие указанного шрифта в Windows — нормальная ситуация: это фильтрация
  при запросе доступных шрифтов, а не повреждение каталога.
- Кэшировать исходный каталог; пересечение с установленными шрифтами выполнять
  при `GetAvailableFonts()`, сохранив существующий порядок и сравнение.
- Для тестов выделить внутреннюю функцию фильтрации с передаваемым списком
  установленных имён, чтобы результат не зависел от компьютера запуска.
- Пустое пересечение возвращает `Consolas`, как сейчас. Ошибка перечисления
  системных шрифтов обрабатывается отдельно от JSON и возвращает тот же резерв
  с диагностикой; она не должна делать валидный список размеров недоступным.
- При ошибке JSON резерв содержит `Consolas` и размеры
  `[10, 11, 12, 13, 14, 16, 18, 20]` и не зависит от ресурса, который не загрузился.

### Специфика тем

- `localizationKey` уникален по `Ordinal`, как в текущем провайдере.
- Для `resourcePath` сохранить проверку относительного URI и расширения
  `.xaml` без учёта регистра. Фактическую поставку и загрузку словарей
  проверять интеграционными тестами; парсер JSON не создаёт WPF-объекты.
- Валидный каталог должен содержать `Theme_VS2022Light` с исходным путём:
  это существующий контракт стартовой темы, модели настроек и резерва.
- Цельный резерв: одна запись
  `Theme_VS2022Light / Themes/VS2022LightTheme.xaml`.
- Проверку непустых названий по точным ключам во всех поставляемых
  `Strings*.resx` выполнять тестом ресурсов, учитывая английский нейтральный
  ресурс. Сам JSON-каталог остаётся независимым от текущей UI-культуры.
- В `ThemeProviderService` сохранить `GetDefaultTheme()`, `TryGetTheme()`,
  сравнение ключей и разрешение старых алиасов. Логику применения XAML,
  сохранения настроек и события `ThemeChanged` оставить в `ThemeService`.

## 8. Риски и принятые решения

- **Строгая проверка меняет обработку повреждённых каталогов.** Раньше часть
  некорректных записей могла молча пропускаться; теперь весь соответствующий
  каталог заменяется резервом. Это запланированная политика, совпадающая
  с подходом языкового каталога; её необходимо явно закрепить тестами.
- **Fallback может скрыть ошибку в поставке.** Одних непустых результатов
  провайдера недостаточно: тесты должны подтверждать наличие JSON и загрузку
  исходного состава без fallback.
- **Набор установленных шрифтов различается.** Проверки каталога и фильтрации
  должны быть независимы от машины запуска; в ручном меню ожидается только
  доступное пересечение либо существующий резерв `Consolas`.
- **Удаление RESX затрагивает локализационный тест.** Его обновление входит
  в обязательный объём, даже при отсутствии изменений `LanguageCatalog`.
- **Валидный путь в JSON не доказывает наличие исправного XAML.** Сохранить
  интеграционную загрузку поставляемых словарей на STA и существующие проверки
  переключения; не переносить создание словарей в парсер каталога.
