**Зависимости:** выполняется первым; его регрессии сохраняются в плане 02.

## 🔎 Проверенная исходная точка

[Существующий переход](NEUTRAL_LANGUAGE_CULTURES.plan.md) уже реализовал
`Strings.resx` в основной сборке, `NeutralResourcesLanguage("en")`,
`Strings.ru.resx` / `Strings.uk.resx`, разрешение региональных алиасов,
нормализацию настроек и общий `GetStringTemplate` для обеих перегрузок.
`SetCultureAsync` вызывает запись и при неизменившемся языке.

`WindowConfigurationService` уже ведёт `_uiLanguageRevision`,
`_persistedUiLanguageRevision` и `_notifiedUiLanguageRevision`: неуспешная
запись допускает повтор; старая успешная запись не подтверждает новый язык.
Эти исправления LOC-04 не нужно проектировать заново.

Остаток LOC-01 виден в `CodeFileService.CodeFileFilter`: используется `??`,
хотя lookup возвращает непустой `[FileFilter_CSharp]`. Структура фильтра
не проверяется. Общая ручная приёмка перехода всё ещё ожидается.
Существующие тесты проверяют ряд fallback/миграций; полного доказательства
удалённой satellite assembly и сквозного UI-сценария они не заменяют.

## 🎯 Целевое поведение

- Штатные коды: `en / ru / uk`; `en-GB → en`, `ru-BY → ru`, `uk-UA → uk`.
  Неизвестное значение из настроек заменяется доступным default `ru`,
  при аварийном английском каталоге — `en`. Прямой непустой неподдерживаемый
  запрос API отклоняется до изменений. Это разные входные границы.
- Общий путь lookup использует английский базовый ресурс; отсутствующий
  во всех наборах ключ остаётся `[ключ]`. Технические свойства имеют
  собственный безопасный fallback, не зависящий от отображаемого маркера.
- Ошибка записи не откатывает уже применённый UI. Повторный выбор того же
  языка повторяет неуспешную запись и ожидает её результат.
- LOC-09 сохраняется: потеря обязательного собственного набора/метаданных
  делает каталог аварийным английским целиком. Не превращать это молча
  в новую политику частичного каталога.

## 🪜 Шаги

1. Зафиксировать исходные проходящие проверки миграции и повторной записи.
   Отделить подтверждённую реализацию от ещё не проверенной приёмки.
2. Реализовать компактную проверку фильтра: непустые пары «описание|маска»,
   чётное число сегментов и непустое содержимое каждой пары. Пустая строка,
   `[FileFilter_CSharp]` и некорректные разделители дают фиксированный
   `C# Files (*.cs)|*.cs|All Files (*.*)|*.*`. Сам резерв проходит ту же проверку.
3. Убедиться, что фильтр доходит и до Open, и до Save As через существующий
   `ICodeFileService`. Не маскировать этим исключения чтения/записи файлов.
4. Проверить реальную цепочку ResourceManager: свой перевод, отсутствие
   отдельного ключа в переводе, отсутствие ru/uk satellite, неизвестный
   ключ во всех наборах. Для отсутствующего ключа использовать тестовый
   набор, не портить production-RESX. Для удалённой сборки — отдельную копию
   публикации и новый процесс, чтобы кэш не скрывал проблему.
5. Подтвердить обе перегрузки `GetString`, в том числе шаблон с аргументами.
   Не вводить изменение provider `string.Format`: это отдельный R15.
6. Пройти «новый язык → IOException → тот же язык → успешная запись → новый
   экземпляр читает JSON». Отдельно сохранить сценарий «старая запись успешна,
   новая неуспешна»: незаписанная новая ревизия остаётся доступна для повтора.
7. После плана 02 повторить эти гарантии через новый координатор переключения.

## 🧪 Проверки

- Для `en`, `ru`, `uk` и старых региональных кодов доступны меню и шаблоны.
- Для `de-DE`, пустого и некорректного значения settings действует записанная
  политика default; прямой неизвестный запрос не меняет состояние и события.
- Любой fallback фильтра присваивается `OpenFileDialog.Filter` и
  `SaveFileDialog.Filter` без `ArgumentException`; показывать диалоги в тесте
  не требуется. Если WPF требует STA, использовать изолированный STA-поток.
- В аварийном каталоге обе перегрузки возвращают английские строки, а каталог
  не выдаёт потерянный перевод за собственный. `[ключ]` допустим только для
  действительно отсутствующего ключа, не как файловый фильтр.
- Неудачная запись видна вызывающему коду; повтор действительно увеличивает
  число записей и восстанавливается после перезапуска. Успешное неизменившееся
  значение не создаёт лишней дисковой записи или `CultureChanged`.
- Ручная проверка: старые настройки, все три языка, галочка, темы, Open,
  Save As и повторный запуск. Сценарий использовать на тестовом профиле,
  не изменять рабочий пользовательский settings.json без необходимости.

Общая команда сборки, запуск наборов и publish-проверка определены
в [плане 06](LOCALIZATION_06_REGRESSION_AND_RELEASE.plan.md).
