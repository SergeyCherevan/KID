# 🗣️ План 03: культура сообщений компилятора и длительных операций

**Статус:** `proposed`. **Дата:** 2026-10-24.
**Пункты аудита:** LOC-02 и соответствующая часть LOC-05.
**Навигация:** [карта планов](LOCALIZATION_AUDIT_CLOSURE_2026-10-24.md).
**Зависимости:** после контракта плана 02; от R15 не зависит.

## 🔎 Проверенная исходная точка

В `CSharpCompiler` Roslyn вызывается как `diagnostic.GetMessage()`.
Оболочка `Error_Compilation` читается из текущего singleton-сервиса.
`CompileAsync` переносит компиляцию в `Task.Run`. Ambient-культура после
`await SetCultureAsync` не обязана совпасть с выбранным языком UI.
В аудите подтверждена смешанная русская оболочка и английский текст Roslyn.

`DefaultCodeRunner.Start` уже фиксирует выбранный язык скрипта; worker
применяет соответствующие UI/formatting-культуры и восстанавливает их.
Это отдельная работа, её не нужно реализовывать повторно или расширять
на глобальные культуры приложения.

## 🎯 Контракт

- `CurrentCulture` локализации — выбранный язык интерфейса `en / ru / uk`.
- Компиляция фиксирует выбранный язык **при входе в `CompileAsync`, до первого
  `await` и постановки `Task.Run`**. Оболочка и все Roslyn-сообщения используют
  этот снимок до конца операции. Переключение UI влияет на следующую компиляцию.
- Выполнение скрипта сохраняет существующую границу снимка `DefaultCodeRunner.Start`.
  Если язык сменили во время компиляции, выполнение может получить уже новый
  язык; это две явно разные операции. Не менять данный контракт неявно.
- Вызов из UI, после `await` или с worker получает один результат при одном
  снимке. Культура вызывающего кода не является источником языка диагностик.
- Для собственных длительных операций, формирующих несколько сообщений,
  использовать такой же снимок, если им требуется единый язык. Мгновенные
  подписи меню продолжают читать текущую культуру.

## 🧩 Решение

Добавить небольшой неизменяемый `LocalizationSnapshot`, получаемый через
`ILocalizationService.CaptureSnapshot()`. Он содержит каноническую `UICulture`
и lookup шаблонов, привязанный к этой культуре. Снимок не читает изменяемое
поле текущего языка при каждом обращении и не сохраняет настройки.

В `CSharpCompiler.CompileAsync` захватить снимок и передать его в синхронный
`Compile`; для каждой диагностики вызывать `diagnostic.GetMessage(snapshot.UICulture)`.
Оболочку `Error_Compilation` получать из того же снимка. Не удерживать
Roslyn Diagnostic в результате: текущая модель строковых ошибок сохраняется.

Форматирование аргументов оболочки до R15 сохраняет действующую политику;
номер строки и текст диагностики не требуют общей переделки чисел/дат.
Снимок должен позволять добавить явный formatting provider в плане 07
без второго механизма lookup.

## 🌍 Переводы Roslyn и fallback

Проверить именно используемую версию Roslyn и фактическую публикацию:
какие переводы CodeAnalysis/CSharp доступны для `ru` и `uk`.
Проверять реальную диагностику с известным ID, а не только наличие папки.

Предлагаемая политика: запрашивать выбранную культуру; при отсутствии
перевода Roslyn разрешать его стандартный английский fallback, сохраняя
переведённую оболочку KID. Для украинского документировать фактическое
поведение и ограничение зависимости. Не подменять его русским без решения
продукта и не обещать перевод всех сообщений стороннего компонента.

Отдельный тест подтверждает русский текст при доступном русском resource set.
Отсутствие переводной satellite проверяется в отдельной копии публикации,
чтобы кэш и файлы IDE не создавали ложное подтверждение.

## 🪜 Шаги и регрессии

1. Воспроизвести на текущем компиляторе `int x = ;` при ambient `en-US`
   и выбранной `ru`; зафиксировать ID и различие текста.
2. Ввести снимок и явный provider, сохранив единый fallback ресурсов KID.
3. Проверить `en / ru / uk`: вызов после `await`, запуск через `Task.Run`,
   несовпадающие системная/выбранная культуры и доступные resource sets Roslyn.
4. Управляемым барьером задержать компиляцию после снимка, сменить язык,
   завершить: весь старый результат на одном языке, следующий — на новом.
   Не использовать тайминги и `Sleep` для порядка.
5. Проверить отсутствие изменений ambient-культуры вызывающего кода как
   допустимое поведение контракта; проверить независимость двух снимков.
6. Прогнать существующие тесты культуры скрипта: выбранный язык на старте,
   собственное переопределение скриптом, восстановление worker-культур.
