# 🌐 Переход локализации KID на ru / uk / en

**Статус:** `implemented` — реализация и автоматизированные проверки выполнены
2026-10-24; ручная приёмка интерфейса ожидается (§ 11).

**Запрос:** заменить региональные коды интерфейса `ru-RU`, `uk-UA`, `en-US`
на языковые `ru`, `uk`, `en` и сохранить совместимость пользовательских настроек.

План подготовлен 2026-10-24. В тот же день пользователь поручил его реализовать
и создать локальный коммит. Ниже сохранены принятые правила и порядок работ;
фактические результаты перечислены в § 11.

## 🎯 1. Целевое поведение

- Поддерживаемые коды и порядок каталога: `en`, `ru`, `uk`.
- Ключи `Language_English`, `Language_Russian`, `Language_Ukrainian`, тексты
  переводов и имя ресурса `KID.Resources.Strings` сохраняются.
- Новый пользователь получает русский интерфейс: `UILanguage = "ru"`.
- Старые настройки автоматически преобразуются: `en-US → en`, `ru-RU → ru`,
  `uk-UA → uk`. Региональные варианты поддерживаемого языка также принимаются:
  например, `en-GB → en`, `ru-BY → ru`.
- Сохранённое значение, свойство сервиса и галочка меню используют один
  канонический код из каталога.
- Пустой, некорректный или неподдерживаемый язык в загруженных настройках
  заменяется на пользовательский default `ru` с диагностикой. Если повреждённый
  каталог доступен только в аварийном варианте `en`, выбирается доступный `en`.
- Резерв ресурсов и аварийный каталог используют `en`. Это отдельная роль:
  русский остаётся начальным языком, английский служит резервом переводов.
- Код языка разрешается по каталогу, с проходом по `CultureInfo.Parent`.
  Список трёх поддерживаемых языков не дублируется в C#.

## 📦 2. Файлы ресурсов и упаковка

### Переименовать три файла

- `KID.WPF.IDE/Resources/Strings.en-US.resx` → `Strings.resx` (язык `en`);
- `KID.WPF.IDE/Resources/Strings.ru-RU.resx` → `Strings.ru.resx`;
- `KID.WPF.IDE/Resources/Strings.uk-UA.resx` → `Strings.uk.resx`.

В каждом файле изменить только значение `Metadata_CultureCode` на соответствующий
языковой код. Ключи, подписи, плейсхолдеры форматирования и технические строки
сохранить. Сравнением XML-данных подтвердить, что остальные значения не изменились.

### Изменить существующие файлы

- `KID.WPF.IDE/Resources/AvailableLanguages.json`: заменить коды на `en`, `ru`,
  `uk`; сохранить порядок и `displayNameKey`.
- `KID.WPF.IDE/KID.WPF.IDE.csproj`: обновить три `EmbeddedResource Update`;
  сохранить генерацию `Strings.Designer.cs` из английского ресурса и проверить,
  что имя класса и базовое имя ResourceManager остались прежними.
- `KID.WPF.IDE/Properties/AssemblyInfo.cs`: добавить `using System.Resources`
  и объявить английский язык базовых ресурсов основной сборки:

```csharp
[assembly: NeutralResourcesLanguage("en")]
```

В этом варианте `Strings.resx` — единственный источник английских строк;
дублирующий `Strings.en.resx` не добавляется. Отсутствие суффикса у файла
не меняет код английского языка в JSON: он равен `en`.

Атрибут действует на всю сборку. В ней уже находятся базовые ресурсы
`AvailableThemes.resx` и `AvailableFontsAndSizes.resx`. Поэтому переключение
общего ultimate fallback на `Satellite` потребовало бы отдельно согласовать
и эти ресурсы. Базовый английский `Strings.resx` сохраняет существующее
размещение каталогов тем и шрифтов в основной сборке.

Такое размещение поддерживается .NET:
[NeutralResourcesLanguageAttribute](https://learn.microsoft.com/en-us/dotnet/api/system.resources.neutralresourceslanguageattribute.-ctor?view=net-10.0),
[порядок поиска ресурсов](https://learn.microsoft.com/en-us/dotnet/core/extensions/package-and-deploy-resources#net-core-resource-fallback-process).

## 🧭 3. Каталог и единое разрешение кодов

**Файл:** `KID.WPF.IDE/Services/Localization/LanguageCatalog.cs`.

1. Заменить аварийную запись `en-US / Language_English` на `en / Language_English`.
2. Добавить внутренний метод разрешения входного кода в код каталога:
   проверка пустого/некорректного значения; поиск точного канонического имени;
   затем проход по родительским культурам до invariant-культуры.
3. Сравнение оставить нечувствительным к регистру; результат всегда брать
   из каталога. Для отсутствующего языка возвращать отсутствие результата.
4. Сохранить строгую проверку JSON, неизменяемость, ленивую однократную загрузку,
   проверку собственных наборов с `tryParents: false` и точных метаданных.
5. Нормализация входа не должна ослаблять проверку поставки: региональный алиас
   разрешается при выборе языка, но запись JSON обязана иметь собственный набор.
   Для `en` этим набором является базовый `Strings.resx`, объявленный атрибутом;
   для `ru` и `uk` — соответствующие satellite-ресурсы. Проверить разрешение `en`
   с `tryParents: false` отдельным интеграционным тестом; общий `tryParents: true`
   вместо проверки собственных ресурсов не вводить.

Примеры: `EN-us → en`, `ru-BY → ru`, `uk-UA → uk`; `de-DE` и некорректное
имя не находят соответствия в текущем каталоге. Не использовать простое
обрезание строки по дефису: проход по родителям подходит и для кодов со скриптом.

## 🔤 4. LocalizationService

**Файл:** `KID.WPF.IDE/Services/Localization/LocalizationService.cs`.

1. Разрешать код в `SetCultureAsync` до сравнения с текущим языком.
   Пустой вход сохраняет существующее поведение «ничего не делать»;
   непустой неподдерживаемый вход отклоняется через `ArgumentException`
   до изменения состояния, событий и настроек.
2. `GetLanguageKeyByCultureCode` использует то же разрешение кодов:
   региональный алиас получает правильный ключ меню, неизвестный код — пустую строку.
   `GetCultureCodeByLanguageKey` возвращает канонический код из JSON.
3. Начальное состояние `_currentCulture` / `CurrentCulture` разрешается
   из системной UI-культуры по каталогу, при отсутствии соответствия — `en`.
   После загрузки настроек применяется выбранный пользователем язык.
4. Для поиска строк и `CurrentUICulture` использовать языковую культуру.
   Привести обе перегрузки `GetString` к одному пути получения шаблона;
   английский ultimate fallback обеспечивает ResourceManager.
   Сохранить `[ключ]` и существующую диагностику для отсутствующего ключа
   или ошибки загрузки ресурсов.
5. Разделить проверку изменения языка и необходимость сохранения настройки.
   Если текущий язык уже `ru`, вход `ru-RU` всё равно должен обеспечить
   сохранение `ru`, когда настройка ещё содержит старый код.
   Не публиковать повторное `CultureChanged` только ради такой записи.
   Вызывать `SetUILanguageAsync` и при совпавшем UI-языке; конфигурационный
   сервис сам пропускает успешно сохранённое неизменившееся значение.
6. Сохранить ожидание записи настроек и распространение её ошибки вызывающему коду.
   Повторный вызов после неудачной записи должен позволять повторить сохранение.

Публичные сигнатуры `ILocalizationService` сохраняются. Правила канонических
результатов и региональных алиасов описать XML-комментариями в
`KID.WPF.IDE/Services/Localization/Interfaces/ILocalizationService.cs`.

### Числа и даты

Для этого перехода предлагается сохранить связь форматирования с выбранным
языком, используя для существующего присваивания `CurrentCulture` результат
`CultureInfo.CreateSpecificCulture(canonicalCode)`. Для текущей Windows/.NET
проверить ожидаемые соответствия `en → en-US`, `ru → ru-RU`, `uk → uk-UA`.
Список соответствий не зашивать в производственный код.

Метод [CreateSpecificCulture](https://learn.microsoft.com/en-us/dotnet/api/system.globalization.cultureinfo.createspecificculture?view=net-10.0)
возвращает связанную региональную культуру. Это позволяет хранить язык
интерфейса без региона, сохранив прежние региональные ориентиры форматирования.

Глобальное распространение ambient-культур через async-вызовы (LOC-02),
явный provider для `string.Format` (отложенный R15), язык Roslyn и отдельная политика
«сохранять региональные настройки Windows» остаются самостоятельными работами.
Этот переход не объявляет их исправленными.

## 💾 5. Миграция настроек

**Файлы:**

- `KID.WPF.IDE/Models/WindowConfigurationData.cs`: default и комментарий — `ru`.
- `KID.WPF.IDE/Services/Initialize/WindowConfigurationService.cs`:
  нормализация загружаемого/записываемого языка и сохранение миграции.

Для использования каталога добавить в конструктор `WindowConfigurationService`
зависимость `ILocalizationService` перед необязательным logger. Канонический
код получить через существующие методы: входной код → ключ языка → код каталога.
Эта операция только читает каталог и не вызывает `SetCultureAsync`.

Проверенная схема зависимостей допускает это: `FileService` уже зависит от
`ILocalizationService`, а конструктор `LocalizationService` не разрешает
`IWindowConfigurationService`; обратное обращение происходит позднее при выборе языка.

Порядок работы:

1. Прочитать JSON и выполнить имеющиеся проверки модели.
2. Разрешить `UILanguage` по каталогу. Отсутствие соответствия заменить на `ru`,
   если он доступен; при аварийном английском каталоге — на `en`.
   Обычный переход `ru-RU → ru` не считать повреждением настроек.
3. Если код загруженного пользовательского языка изменился, сохранить
   канонический код через существующий `SaveSettingsAsync` и дождаться записи.
   Не выполнять дополнительную запись при каждом последующем запуске.
4. Выполнять запись миграции вне `catch`, обслуживающего ошибки чтения:
   сбой записи не должен превращаться в сообщение об ошибке чтения и сброс настроек.
5. При отсутствии пользовательского файла сохранить нормализованные настройки
   один раз существующим путём создания файла.
6. В `SetUILanguageAsync` также разрешать вход до сравнения. Сравнивать
   канонический результат с фактически сохранённым в `Settings` значением:
   старый код требует записи даже при том же языке интерфейса.
   Непустой неподдерживаемый вход отклонять до изменения состояния,
   пустой вход сохраняет существующее поведение «ничего не делать».
7. Отслеживать незавершённое сохранение языка: ошибка записи оставляет его
   ожидающим повторной попытки, даже когда `Settings.UILanguage` уже изменён
   в памяти. Снимать этот признак только после успешной записи; завершение
   старой записи не должно снимать признак более нового изменения.
8. После успешного изменения настройки сохранить существующее уведомление
   `UILanguageSettingsChanged`; не дублировать события без изменения значения.

Некорректный JSON / null обязательных полей сохраняют действующую обработку
ошибок чтения; автоматическое переписывание такого исходного файла в эту миграцию
не добавляется. Все успешные записи используют существующую очередь и атомарную
запись FileService.
