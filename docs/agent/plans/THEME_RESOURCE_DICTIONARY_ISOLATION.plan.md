## 1. 🎯 Результат и границы задачи

Обеспечить переключение темы без удаления остальных подключённых словарей
ресурсов приложения. Выделить постоянный `ThemeResourceContainer`, внутри
которого находится ровно один словарь активной темы.

При переключении заменяется только этот внутренний словарь. Сохраняются
объекты остальных словарей, их содержимое, порядок и положение контейнера
в `Application.Resources.MergedDictionaries`.

В границы реализации входят:

- явное обозначение контейнера темы небольшим типом WPF;
- размещение начальной темы из `App.xaml` внутри контейнера;
- замена глобального `Clear()` на адресную замену активной темы;
- проверка структуры контейнера до изменения ресурсов;
- проверки сохранения посторонних ресурсов и обновления существующих элементов;
- актуализация конкретного пункта аудита после подтверждённой реализации.

Не требуется менять палитры, цвета, размеры, шаблоны, каталог и названия тем,
ключи настроек, локализацию, публичный `IThemeService`, регистрацию DI,
порядок инициализации окна или исполнение пользовательских программ.
Не добавлять новые темы, библиотеки, фабрики или отдельную систему загрузки ресурсов.

## 2. 🔎 Исторический снимок до реализации (2026-10-13)

### 2.1. Начальная загрузка ресурсов

[App.xaml](../../../KID.WPF.IDE/App.xaml) подключает
`Themes/VS2022LightTheme.xaml` непосредственно к корневому словарю приложения.
Сейчас это единственный словарь во внешней коллекции `MergedDictionaries`.

Сами темы подключают вложенные словари размеров и шаблонов:
`VS2022Metrics.xaml` / `VS2026Metrics.xaml`, `MenuStyles.xaml`,
`WindowStyles.xaml`, `EditorTabStyles.xaml`, а VS2026 также
`EditorScrollStyles.xaml`. Они находятся внутри словаря темы и загружаются
вместе с ним. Их наличие не означает, что у приложения уже есть независимые
от темы словари во внешней коллекции.

### 2.2. Каталог и выбор темы

[AvailableThemes.resx](../../../KID.WPF.IDE/Resources/AvailableThemes.resx)
содержит четыре канонические темы в порядке меню:

1. `Theme_VS2022Light` → `Themes/VS2022LightTheme.xaml`.
2. `Theme_VS2022Dark` → `Themes/VS2022DarkTheme.xaml`.
3. `Theme_VS2026Light` → `Themes/VS2026LightTheme.xaml`.
4. `Theme_VS2026Dark` → `Themes/VS2026DarkTheme.xaml`.

[ThemeProviderService](../../../KID.WPF.IDE/Services/Themes/ThemeProviderService.cs)
читает каталог, возвращает [ThemeDefinition](../../../KID.WPF.IDE/Models/ThemeDefinition.cs)
и поддерживает старые ключи `Theme_Light` / `Theme_Dark`.
Тема по умолчанию — VS2022 Light. Описание темы содержит ключ и путь;
загруженный WPF-словарь создаётся отдельно.

### 2.3. Входы в применение темы

- При запуске [MainWindow](../../../KID.WPF.IDE/MainWindow.xaml.cs)
  вызывает инициализацию после `Loaded`.
  [WindowInitializationService](../../../KID.WPF.IDE/Services/Initialize/WindowInitializationService.cs)
  сначала загружает настройки, затем передаёт `Settings.ColorTheme` в `ApplyTheme()`.
- При выборе через меню [MenuViewModel](../../../KID.WPF.IDE/ViewModels/MenuViewModel.cs)
  передаёт `ThemeDefinition.LocalizationKey` в тот же метод.
- [ThemeService](../../../KID.WPF.IDE/Services/Themes/ThemeService.cs)
  зарегистрирован как singleton в
  [ServiceCollectionExtensions](../../../KID.WPF.IDE/Services/DI/ServiceCollectionExtensions.cs).

### 2.4. Применение и уведомления

До реализации `ThemeService`:

1. Разрешает ключ через каталог; неизвестный ключ заменяет темой по умолчанию.
2. Формирует URI с явным именем сборки KID и загружает новый `ResourceDictionary`.
3. Проверяет доступность ресурсов приложения.
4. Очищает все `app.Resources.MergedDictionaries` и добавляет новую тему.
5. Обновляет `CurrentTheme`.
6. Через `IAsyncOperationErrorHandler` запускает сохранение канонического ключа.
7. Вызывает `ThemeChanged`.

При ошибке применения выбранной темы сервис пытается применить тему по умолчанию,
если она отличается от выбранной, затем сообщает об исходной ошибке.

`MenuViewModel` по событию обновляет выбранный пункт меню.
[CodeEditorsViewModel](../../../KID.WPF.IDE/ViewModels/CodeEditorsViewModel.cs)
назначает актуальную палитру открытым `RoslynCodeEditor`.
[ClassificationHighlightColorsProvider](../../../KID.WPF.IDE/Services/CodeEditor/ClassificationHighlightColorsProvider.cs)
ищет `CodeEditorClassificationColors` через `app.TryFindResource()`.
WPF-оформление использует, в частности, ссылки `DynamicResource`.

## 3. 🧹 Проблема и ожидаемое поведение

Операция на исходном снимке:

```csharp
app.Resources.MergedDictionaries.Clear();
app.Resources.MergedDictionaries.Add(themeDictionary);
```

удаляет подключения всех словарей внешней коллекции, независимо от владельца.
Она не удаляет XAML-файлы, не очищает напрямую `Window.Resources` и не удаляет
непосредственные записи корневого `app.Resources`.

На исходном снимке видимый дефект из этого условия не подтверждён: внешняя коллекция
содержит только тему. Риск возникает, если там появятся независимые ресурсы.

Пример будущей конфигурации:

```text
До:    [Общие иконки] [Текущая тема] [Ресурсы библиотеки]
Сейчас после переключения: [Новая тема]
Нужно: [Общие иконки] [Новая тема] [Ресурсы библиотеки]
```

Удаление подключения может нарушить последующий поиск ресурсов и оформление.
Уже полученные статические ссылки могут продолжать работать, поэтому отсутствие
мгновенной поломки не доказывает сохранность подключения.

## 4. 🏗️ Предлагаемая структура ресурсов

### 4.1. Постоянный контейнер

Добавить файл
`KID.WPF.IDE/Services/Themes/ThemeResourceContainer.cs`:

```csharp
using System.Windows;

namespace KID.Services.Themes;

public sealed class ThemeResourceContainer : ResourceDictionary
{
}
```

Тип служит однозначным маркером назначения словаря. Он остаётся обычным
`ResourceDictionary`, участвует в стандартном поиске ресурсов WPF и не требует
собственной логики загрузки. Публичная видимость нужна для использования в XAML.
Это не описание конкретной темы и не замена `ThemeDefinition`.

### 4.2. Начальная тема внутри контейнера

В `App.xaml` добавить пространство имён
`xmlns:themes="clr-namespace:KID.Services.Themes"` и обернуть существующее
подключение темы:

```xml
<Application.Resources>
    <ResourceDictionary>
        <ResourceDictionary.MergedDictionaries>
            <themes:ThemeResourceContainer>
                <ResourceDictionary.MergedDictionaries>
                    <ResourceDictionary Source="Themes/VS2022LightTheme.xaml"/>
                </ResourceDictionary.MergedDictionaries>
            </themes:ThemeResourceContainer>
        </ResourceDictionary.MergedDictionaries>
    </ResourceDictionary>
</Application.Resources>
```

Начальная тема должна быть доступна уже при разборе XAML главного окна,
до применения настроек. Не переносить её первоначальную загрузку в событие `Loaded`.

Будущие общие ресурсы подключаются рядом с контейнером, а не внутрь него:

```text
Application.Resources
├── непосредственные ресурсы корневого словаря
└── MergedDictionaries
    ├── независимый общий словарь, если появится
    ├── ThemeResourceContainer — постоянный объект
    │   └── MergedDictionaries
    │       └── активная тема — единственный заменяемый словарь
    │           └── её вложенные словари размеров и шаблонов
    └── независимый словарь библиотеки, если появится
```

### 4.3. Инварианты

- Во внешней коллекции есть ровно один `ThemeResourceContainer`.
- В его `MergedDictionaries` находится ровно один словарь активной темы.
- Контейнер не имеет собственного `Source` и непосредственных записей ресурсов:
  он служит только постоянным местом подключения темы.
- Общие ресурсы приложения не помещаются в контейнер темы.
- `ThemeService` меняет только внутренний словарь темы на UI-потоке,
  как в действующих путях вызова.
- Объект контейнера, его позиция и внешняя коллекция сохраняются.

Прямые записи контейнера могли бы перекрыть ключи вложенной темы.
Проверка структуры должна отклонять такую конфигурацию до замены.
Проверять верхний уровень, не искать контейнер рекурсивно внутри тем.

## 5. ⚙️ Алгоритм изменения ThemeService

Сохранить существующее разрешение ключей и создание URI с именем сборки.
Новый словарь по-прежнему загружать до изменения действующего дерева ресурсов.

После загрузки:

1. Проверить доступность `app.Resources`.
2. Найти единственный контейнер среди непосредственных элементов
   `app.Resources.MergedDictionaries` по типу `ThemeResourceContainer`.
3. Проверить все инварианты контейнера.
4. Выполнить единственную адресную замену:

   ```csharp
   themeContainer.MergedDictionaries[0] = themeDictionary;
   ```

5. Затем сохранить существующий порядок обновления `CurrentTheme`, запуска
   сохранения настройки и публикации `ThemeChanged`.

Индекс `0` относится только к внутренней коллекции, размер которой проверен.
Не полагаться на фиксированный индекс темы во внешней коллекции.
Не выполнять внешние `Clear()`, `Remove()` или повторный `Add()` контейнера.
Не искать тему по подстроке пути и не удалять все словари каталога `Themes/`.

Для проверки реальной производственной операции выделить внутри `ThemeService`
небольшой `internal static` метод, например:

```csharp
internal static void ReplaceThemeDictionary(
    ResourceDictionary applicationResources,
    ResourceDictionary themeDictionary)
```

Метод получает уже загруженный словарь, находит и проверяет контейнер,
затем заменяет тему. Его вызывает `TryApplyTheme`; тесты вызывают этот же метод
на локальном дереве ресурсов. Он не выбирает тему, не читает настройки,
не публикует события и не создаёт `Application`.
В сборке IDE уже есть `InternalsVisibleTo("KID.Tests")`.

Не добавлять ради тестов новый публичный конструктор, интерфейс управления
ресурсами или альтернативный механизм применения темы.

## 6. 🛡️ Ошибки, совместимость и ограничения гарантий

При отсутствии контейнера, двух контейнерах, неверном числе внутренних
словарей, собственном `Source` или непосредственных записях контейнера:

- выбросить понятный `InvalidOperationException` до изменения дерева;
- передать ошибку через существующий путь `TryApplyTheme` / `ApplyTheme`;
- не создавать контейнер молча и не возвращаться к глобальному `Clear()`;
- не менять ресурсы, `CurrentTheme`, настройки и не публиковать `ThemeChanged`
  для такой неуспешной попытки.

Существующая попытка применить резервную тему сохраняется. Ошибка структуры
не исправляется сменой файла темы: резервная попытка также должна завершиться
без удаления посторонних ресурсов.

При ошибке загрузки XAML до замены прежняя тема остаётся подключённой.
Это ограниченная гарантия для загрузки и проверки структуры, а не обещание
полной транзакционности всей операции. Сейчас общий `catch` также охватывает
обновление состояния и вызов подписчиков; исключение после замены ресурсов
не означает автоматический откат. Переработка этой семантики — отдельная задача.

Сохранить:

- все четыре темы, их порядок, ключи и пути;
- миграцию старых ключей `Theme_Light` / `Theme_Dark`;
- начальную и резервную тему VS2022 Light;
- существующее сохранение канонического ключа;
- доступность палитры через `TryFindResource`;
- уведомления меню и обновление уже открытых редакторов.

## 7. ⚖️ Порядок поиска ресурсов и выбранное решение

При одинаковых ключах в нескольких подключённых словарях WPF выбирает ресурс
из последнего словаря. Непосредственные записи родительского словаря имеют
приоритет над подключёнными. Поэтому сохранять позицию контейнера необходимо:
удаление и добавление в конец могло бы поменять выбор конфликтующих ресурсов.

Дополнительный уровень контейнера должен сохранить доступ к ресурсам темы
через приложение; это требуется подтвердить тестом динамических ссылок и
ручным запуском с реальным `App.xaml`.

Рассмотренные альтернативы:

- Ссылка на активный словарь без контейнера: меньше XAML, но требуется отдельно
  распознать и принять во владение первоначальный словарь из `App.xaml`.
- Поиск по `Source`: требует правил сравнения URI и привязывает владение
  к имени файла; изменения путей и другой WPF-хост усложняют распознавание.
- Контейнер с явным типом: назначение видно в XAML, первоначальная тема уже
  находится внутри, а переключение не затрагивает соседние словари.

Для этой задачи выбран третий вариант.

Справочные правила WPF:

- [Merged resource dictionaries](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/systems/xaml-resources-merged-dictionaries).
- [XAML resources overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/systems/xaml-resources-overview).

## 9. 🧪 Автоматические проверки

### 9.1. Сохранение независимых ресурсов

Новый `KID.Tests/Themes/ThemeResourceIsolationTests.cs` использует
[StaTest](../../../KID.Tests/Infrastructure/StaTest.cs) и локальный

Собрать дерево: словарь до контейнера, контейнер с начальной темой, словарь
после контейнера и непосредственный ресурс корневого словаря.
Вызвать производственный `ReplaceThemeDictionary()`.

Проверить:

- внешнее число словарей и порядок не изменились;
- контейнер и соседние словари остаются теми же объектами;
- их ресурсы и непосредственный корневой ресурс доступны;
- контейнер содержит только новую тему;
- повторные замены не накапливают старые темы;
- одинаковый ключ в соседних словарях разрешается с прежним приоритетом;
- при отсутствии перекрывающего ключа доступен ресурс новой темы.

### 9.2. Некорректная структура

Проверить отдельно: нет контейнера, два контейнера, пустая внутренняя
