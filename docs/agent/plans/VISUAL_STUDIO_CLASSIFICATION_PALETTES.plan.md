# 🎨 План классов палитр VS2022 и VS2026

**Статус:** completed — реализация завершена; результаты проверок ниже.

**Обновлён:** 2026-10-12 по уточнению пользователя.

## 1. 🧩 Три новых класса и одно переименование

Добавить в KID.WPF.IDE/Services/CodeEditor/ три файла:

1. VS2022LightClassificationHighlightColors.cs.
2. VS2026LightClassificationHighlightColors.cs.
3. VS2026DarkClassificationHighlightColors.cs.

Переименовать существующий файл и класс DarkClassificationHighlightColors
в VS2022DarkClassificationHighlightColors, включая имя конструктора.
**Во всех четырёх классах цвета и начертания должны соответствовать
заводскому оформлению своей версии и темы VS. При переименовании существующую
тёмную палитру также привести к VS2022 Dark, обновив цвета, начертания
и карту категорий.**

Каждый новый класс самостоятельно реализует
RoslynPad.Editor.IClassificationHighlightColors по образцу существующей
тёмной палитры: кисти, карта классификаций, DefaultBrush, GetBrush(string).
Классы доступны из XAML и имеют публичный конструктор без параметров.

Общая база, фабрика профилей, вспомогательные модели и новые интерфейсы
не нужны. Допускается дублирование кода между палитрами.

## 2. 🎨 Наполнение всех четырёх палитр

Для всех четырёх классов, включая переименованный тёмный, использовать
проверенные заводские цвета и начертания VS из исследования в этом чате.
Каждый класс соответствует версии и светлой/тёмной теме, указанным в его
имени. Проверенные сборки:
VS2022 17.14.37628.2, VS2026 18.10.12224.181.

Основные светлые цвета C# в этих сборках совпадают, поэтому новые
VS2022LightClassificationHighlightColors и
VS2026LightClassificationHighlightColors первоначально могут содержать
одинаковые значения. Отдельные имена классов сохраняются.

Основные тёмные цвета C# также совпадают в проверенных сборках.

Поля, свойства, события, константы и пространства имён используют обычный
цвет текста. Неизвестная категория возвращает DefaultBrush.

Во всех четырёх палитрах обычные категории не получают принудительный Bold/Italic.
Для StaticSymbol использовать нейтральный стиль без собственного цвета
и жирного начертания. Если приходят ReassignedVariable и ObsoleteSymbol,
оформлять их через Underline и Strikethrough без замены основного цвета.
Для распознанного regex использовать исследованные стили;
RegexSelfEscapedCharacter получает Bold.

Эти правила относятся **ко всем четырём классам**. В переименованном
VS2022DarkClassificationHighlightColors заменить прежние оттенки на значения
VS2022 Dark, разделить категории согласно таблице и убрать жирное начертание
StaticSymbol. Прежнее оформление KID не сохранять как исключение.

Остальные возвращаемые палитрами цвета и начертания, включая regex
и подсветку пары скобок, также брать из заводских определений соответствующей
VS. Недостающие значения проверить перед реализацией; не оставлять
приблизительные оттенки старой палитры или RoslynPad.

При реализации подтверждён фон подсветки парных скобок: #DBE0CC для светлых
палитр, #0E4583 для тёмных. Светлое значение проверено по
[определению BraceMatching Microsoft Roslyn](https://github.com/dotnet/roslyn/blob/98b902d22362d3fe1eb01b492328d605f1ceeb05/src/EditorFeatures/Core/BraceMatching/BraceMatchingTypeFormatDefinitions.cs),
тёмное — по заводским ресурсам обеих установленных VS.

Источники для значений и начертаний:

- [Цветовая схема Microsoft Roslyn](https://github.com/dotnet/roslyn/blob/98b902d22362d3fe1eb01b492328d605f1ceeb05/src/VisualStudio/Core/Def/ColorSchemes/VisualStudio2019.xml).
- [Определения оформления Microsoft Roslyn](https://github.com/dotnet/roslyn/blob/98b902d22362d3fe1eb01b492328d605f1ceeb05/src/EditorFeatures/Core/Classification/ClassificationTypeFormatDefinitions.cs).

## 3. 🔄 Подключение к существующим темам

1. В [LightTheme.xaml](../../../KID.WPF.IDE/Themes/LightTheme.xaml)
   использовать VS2022LightClassificationHighlightColors вместо
   стандартного ClassificationHighlightColors RoslynPad.
2. В [DarkTheme.xaml](../../../KID.WPF.IDE/Themes/DarkTheme.xaml)
   обновить ссылку на переименованный VS2022DarkClassificationHighlightColors.
3. В [ClassificationHighlightColorsProvider.cs](../../../KID.WPF.IDE/Services/CodeEditor/ClassificationHighlightColorsProvider.cs)
   заменить только резервную светлую палитру на
   VS2022LightClassificationHighlightColors.
4. Сохранить существующий ключ ресурса CodeEditorClassificationColors
   и действующий механизм смены палитры.

**Обе палитры VS2026 пока нигде не подключать.** Они будут использоваться
позже, когда появятся новые темы окна под VS2026.

Существующие цвета окна и фон/Foreground редактора не менять.
Новые темы окна, переключатель версии, настройки, DI-сервисы, изменение
фабрики редакторов и механизма ThemeChanged в эту задачу не входят.

## 4. 🛠️ Порядок работ

1. Переименовать существующий тёмный класс, файл, конструктор и ссылки;
   привести его цвета, начертания и карту категорий к VS2022 Dark.
2. Добавить три самостоятельных класса палитр с заводским оформлением
   соответствующих версий и тем VS.
3. Подключить VS2022 Light к существующей светлой теме и резервной палитре.
4. Убедиться, что палитры VS2026 нигде не используются.
5. Обновить только упоминания классов/активных палитр в документации.

Не добавлять окраску скобок по вложенности, новые классификаторы,
настройки подчёркивания или другие механизмы редактора.
