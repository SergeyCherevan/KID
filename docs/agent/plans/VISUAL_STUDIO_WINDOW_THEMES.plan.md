# 🎨 План тем окна и UI Visual Studio 2022 / 2026

**Статус:** completed — темы и миграция реализованы; технические проверки и ограничения визуального соответствия записаны в разделе 11.

**Создан и проверен по исходному коду:** 2026-10-12.

**Исходная ветка:** `feature/AddVSHighlightColors`.

**Исходный коммит:** `3787031993f6233e076d21eb94b99ec6cc58e8ca`
(`feat(editor): add Visual Studio classification palettes`).

Документ описывает следующие изменения относительно указанного снимка.
Перед реализацией повторно проверить ветку, рабочее дерево и исходники.
Исторические результаты проверок другого плана не являются проверками этой задачи.

## 1. 🎯 Результат и границы задачи

Переименовать существующие темы во всём проекте:

- `LightTheme.xaml` → `VS2022LightTheme.xaml`.
- `DarkTheme.xaml` → `VS2022DarkTheme.xaml`.

Добавить `VS2026LightTheme.xaml` и `VS2026DarkTheme.xaml`, воспроизводящие
стандартное оформление окна и соответствующих элементов UI Visual Studio 2026:
заголовок, кнопки окна, меню и всплывающие меню, вкладки редактора,
их кнопки закрытия, поверхности рабочей зоны, границы и разделители.

Новые темы подключают уже существующие палитры синтаксической подсветки VS2026.
Выбор доступен через действующее меню тем и сохраняется между запусками.

Переименование VS2022 сохраняет текущее оформление KID. Оно само по себе
не означает, что все существующие цвета оболочки проверены на точное
соответствие заводской VS2022: такая переработка старых тем не входит в план.

Реализация остаётся на WPF. «Наследование стиля VS2026» означает перенос
проверенных цветов и параметров оформления в собственные ресурсы и шаблоны KID.
Файл темы Visual Studio не является WPF `ResourceDictionary`, а `BasedOn`
не позволяет наследовать произвольный стиль из установленной внешней программы.

Новые зависимости от установленной Visual Studio, новые NuGet-библиотеки,
переход на WinUI, перестройка рабочих панелей, новые команды и отдельная
настройка версии оформления не требуются. Не менять код компиляции,
выполнения программ, рисования, ввода/вывода и языковых классификаторов.

## 2. 🔎 Исторический снимок до реализации (2026-10-12)

1. [App.xaml](../../../KID.WPF.IDE/App.xaml) загружает `Themes/LightTheme.xaml`
   до применения пользовательских настроек.
2. [AvailableThemes.resx](../../../KID.WPF.IDE/Resources/AvailableThemes.resx)
   содержит две записи с ключами `Theme_Light` / `Theme_Dark` и путями к XAML.
3. [ThemeProviderService.cs](../../../KID.WPF.IDE/Services/Themes/ThemeProviderService.cs)
   читает упорядоченный каталог, разрешает ключи точным сравнением
   и имеет резервную тему `Theme_Light` / `Themes/LightTheme.xaml`.
4. [ThemeDefinition.cs](../../../KID.WPF.IDE/Models/ThemeDefinition.cs)
   связывает ключ локализации, который одновременно служит идентификатором,
   и путь к словарю. Изменение этой модели не требуется.
5. [ThemeService.cs](../../../KID.WPF.IDE/Services/Themes/ThemeService.cs)
   загружает новый словарь, очищает `Application.Resources.MergedDictionaries`,
   добавляет словарь темы, сохраняет успешно применённый ключ и публикует
   `ThemeChanged`. Неизвестный ключ приводит к теме по умолчанию.
6. [WindowInitializationService.cs](../../../KID.WPF.IDE/Services/Initialize/WindowInitializationService.cs)
   применяет `Settings.ColorTheme` после загрузки настроек.
7. [WindowConfigurationData.cs](../../../KID.WPF.IDE/Models/WindowConfigurationData.cs)
   и [DefaultWindowConfiguration.json](../../../KID.WPF.IDE/DefaultWindowConfiguration.json)
   задают `Theme_Light`. JSON копируется в выходной каталог приложения.
8. [MenuView.xaml](../../../KID.WPF.IDE/Views/MenuView.xaml)
   и [MenuViewModel.cs](../../../KID.WPF.IDE/ViewModels/MenuViewModel.cs)
   строят пункты из каталога. Названия локализуются по ключу, галочка
   сравнивает его с `CurrentTheme.LocalizationKey`.
9. [MainWindow.xaml](../../../KID.WPF.IDE/MainWindow.xaml) использует собственный
   заголовок и `WindowChrome`. Размеры, интервалы и часть оформления заданы
   локально; отдельного неявного стиля `Window` для изменения этого недостаточно.
10. [MenuStyles.xaml](../../../KID.WPF.IDE/Themes/MenuStyles.xaml) уже подключается
    внутри обоих словарей тем. Цвета параметризованы, геометрия задана константами.
11. [CodeEditorsView.xaml](../../../KID.WPF.IDE/Views/CodeEditorsView.xaml)
    содержит локальные стили вкладок и прокрутки, inline-триггеры выбора
    и ссылки `StaticResource` на стили. Некоторые размеры заданы прямо на элементах.
12. Все четыре класса `VS2022LightClassificationHighlightColors`,
    `VS2022DarkClassificationHighlightColors`, `VS2026LightClassificationHighlightColors`
    и `VS2026DarkClassificationHighlightColors` уже существуют в
    `KID.WPF.IDE/Services/CodeEditor/`. Действующие темы используют VS2022;
    новые классы создавать или переименовывать не нужно.
13. [ClassificationHighlightColorsProvider.cs](../../../KID.WPF.IDE/Services/CodeEditor/ClassificationHighlightColorsProvider.cs)
    получает палитру по ключу `CodeEditorClassificationColors`, с резервной
    палитрой VS2022 Light. [CodeEditorsViewModel.cs](../../../KID.WPF.IDE/ViewModels/CodeEditorsViewModel.cs)
    по `ThemeChanged` обновляет все открытые `RoslynCodeEditor`.
14. Раздел «Добавление новой темы» в
    [DEVELOPMENT.md](../../DEVELOPMENT.md) описывает отсутствующие
    `ThemeService.GetAvailableThemes()` и `AvailableTheme`; его требуется исправить.

## 3. 🏷️ Имена, порядок каталога и совместимость

Канонические определения после реализации:

1. `Theme_VS2022Light` → `Themes/VS2022LightTheme.xaml`.
2. `Theme_VS2022Dark` → `Themes/VS2022DarkTheme.xaml`.
3. `Theme_VS2026Light` → `Themes/VS2026LightTheme.xaml`.
4. `Theme_VS2026Dark` → `Themes/VS2026DarkTheme.xaml`.

Порядок одинаков во всех языках. Тема по умолчанию и резервная тема —
`Theme_VS2022Light`. Новая установка, стартовый словарь `App.xaml`, модель
настроек и поставляемый JSON должны согласованно выбирать эту тему.

Предлагаемые отображаемые названия:

- ru-RU: «Visual Studio 2022 — светлая», «Visual Studio 2022 — тёмная»,
  «Visual Studio 2026 — светлая», «Visual Studio 2026 — тёмная».
- en-US: «Visual Studio 2022 — Light», «Visual Studio 2022 — Dark»,
  «Visual Studio 2026 — Light», «Visual Studio 2026 — Dark».
- uk-UA: «Visual Studio 2022 — світла», «Visual Studio 2022 — темна»,
  «Visual Studio 2026 — світла», «Visual Studio 2026 — темна».

Старые сохранённые идентификаторы поддержать в одном месте:
`ThemeProviderService.TryGetTheme` нормализует `Theme_Light` и `Theme_Dark`
в соответствующие канонические ключи перед поиском.
В каталог старые записи не добавлять; в меню остаются ровно четыре темы.

После разрешения старого ключа сервис возвращает канонический `ThemeDefinition`.
Успешное применение через `ThemeService` запускает существующее сохранение
нового ключа. Завершение дисковой записи асинхронно: проверять сохранённый JSON
после завершения операции, а не сразу после возвращения `ApplyTheme`.
При ошибке сохранения действует существующий обработчик ошибок.

Неизвестные, пустые и null-ключи сохраняют существующий fallback на светлую
тему VS2022. Миграция не должна превращать старую тёмную тему в светлую.
Старые ключи остаются только в совместимости, её проверках и пояснениях миграции.

## 4. 🎨 Проверка эталона VS2026 до написания новых словарей

**Подготовлено 2026-10-12:** [справочник цветов и параметров VS2026](VS2026_UI_REFERENCE.md)
и [машиночитаемые заводские значения](VS2026_UI_REFERENCE.json).
Через `vswhere` подтверждена установленная VS2026 18.10.3,
сборка `18.10.12224.181`. Прочитаны заводские pkgdef, BAML и размерные
константы без изменения настроек VS. Справочник разделяет подтверждённые
значения, предложения переноса в KID и ещё не выполненные runtime-проверки.
Перед реализацией использовать этот результат вместо повторного исследования
уже проверенных параметров; открытые проверки остаются перечислены в справочнике.

Сначала получить эталон стандартных Light/Dark конкретной сборки VS2026.
Зафиксировать версию, источник ресурсов и отсутствие пользовательских
цветовых переопределений. Существующий
[план палитр](VISUAL_STUDIO_CLASSIFICATION_PALETTES.plan.md) ссылается на
VS2026 `18.10.12224.181`, но это историческое свидетельство для подсветки,
а не текущая проверка цветов и геометрии оболочки.

Предпочтительно сверить оболочку с той же сборкой, если она доступна.
Если используется другая, записать точную версию и возможные отличия.
Для получения заводского эталона не сбрасывать настройки основной VS пользователя:
использовать исходные ресурсы или отдельную среду проверки.

Официальные ориентиры:

- [Modernize Visual Studio theme colors](https://learn.microsoft.com/en-us/visualstudio/extensibility/migration/modernize-theme-colors?view=visualstudio):
  семантические цвета Fluent, разделение оболочки и синтаксической подсветки.
- [A first look at the all-new UX in Visual Studio 2026](https://devblogs.microsoft.com/visualstudio/a-first-look-at-the-all%E2%80%91new-ux-in-visual-studio-2026/):
  визуальные примеры, типографика, значки и интервалы.

Проверенные значения и их происхождение записать в этот документ перед
этапом реализации VS2026. Примеры цветов из руководства по миграции
не принимать автоматически за полное описание заводской темы.

Для каждой светлой/тёмной темы определить:

- Фон оболочки, заголовка, панели меню, popup/context menu и рабочей зоны.
- Фоны редактора и текста, активной/неактивной вкладки и полосы вкладок.
- Основной и вторичный текст, границы, разделители, акцент и индикатор выбора.
- Состояния hover, pressed, selected, disabled и клавиатурного focus.
- Высоту заголовка и вкладок, размеры кнопок, отступы, толщины границ,
  скругления, шрифт и размер текста UI.
- Геометрию значков управления окном и закрытия вкладки, если для
  соответствия VS2026 требуется заменить текущие текстовые символы.

Фон консоли связать с соответствующей поверхностью вывода; фон графической
области выбрать отдельно с учётом читаемости пользовательских рисунков.
Не перекрашивать выводимые программой текстовые сегменты и графические объекты.
Существующие настройки шрифта редактора должны сохранять приоритет.

Сведения о недоступных или неподтверждённых параметрах отмечать явно.
Без проверки оболочки не объявлять новые темы точной копией VS2026.

Уточнения по результатам исследования: активная документная вкладка VS2026
имеет фон `EnvironmentTab` и акцентную границу; для этого нужны новые ключи
границ вкладок. Её горизонтальный шаблон использует `TopCurvedBorder` с нижними
внешними сопряжениями, которые не воспроизводит обычный `Border.CornerRadius`.
В рамках переноса при необходимости добавить собственную геометрию или
минимальный контрол KID (предлагаемый путь `KID.WPF.IDE/Controls/EditorTabBorder.cs`);
численные параметры взять из справочника, внутренние сборки VS не подключать.
Также разделить popup border и hover border пункта меню, добавить состояния
Close/неактивного окна и focus. Главный заголовок не смешивать с заголовком
внутренней панели: источники и ограничения приведены в справочнике.

## 5. 🧩 Организация ресурсов и переключение оформления

Сохранить текущий механизм: приложение содержит один корневой словарь
активной темы, а общие словари подключаются внутри него.
`ThemeService` в этом варианте не требует изменения.
Не размещать новые общие словари рядом с темой в
`Application.Resources.MergedDictionaries`: текущий `Clear()` удалит их.

Каждый из четырёх корневых словарей объявляет совместимый набор:

- Существующие ключи цветов и кистей, используемые представлениями.
- Параметры геометрии и типографики, нужные для различий VS2022/VS2026.
- `WindowButtonStyle` и другие необходимые именованные стили.
- Палитру по прежнему ключу `CodeEditorClassificationColors`.
- Подключение общих словарей меню, вкладок и оформления окна.

Сохранить `MenuStyles.xaml`; добавить `EditorTabStyles.xaml` и
`WindowStyles.xaml` для вынесенного оформления. Общие шаблоны использовать
там, где различия выражаются ресурсами. Если эталон требует иной структуры
шаблона, разместить переопределение в соответствующих корневых темах.
Не строить новую систему профилей или наследования моделей тем.

Минимальные дополнительные параметры выбирать по реально найденным различиям:
высота заголовка/вкладки, размер и отступы кнопок, радиусы popup/вкладки,
толщины границ, шрифт UI и интервалы. Значения VS2022 повторяют прежние константы.
Ресурс имеет тип ожидаемого свойства: `double`, `Thickness`, `CornerRadius`,
`GridLength` и т. п.; один числовой ресурс нельзя без проверки использовать
и как `Height`, и как `RowDefinition.Height`.

Для ресурсов, меняющихся вместе с темой, использовать `DynamicResource`
на допустимых WPF dependency properties и в setters. Для неизменных
конвертеров и структурных ресурсов допустим `StaticResource`.
Отдельно проверить порядок разрешения ресурсов вложенных словарей:
общие шаблоны не должны через `StaticResource` требовать ещё не загруженные
цвета или метрики родительской темы.

Особые места при переносе:

1. Локальные значения свойств перекрывают setters. Удалить или
   параметризовать именно те константы, которые мешают смене оформления.
2. Локальные стили `CodeEditorsView` могут скрывать одноимённые ресурсы темы.
   Вынести оформление вкладок, не теряя триггеры текущей вкладки и её закрытие.
3. Перенесённые стили сделать самодостаточными в отношении конвертеров;
   не оставлять `StaticResource` на конвертер, доступный только в старой области.
   Контекстные меню с `x:Reference CodeEditorsViewRoot` оставить в представлении.
4. `MenuView` содержит `BasedOn="{StaticResource ...}"`. Такая ссылка
   может сохранить старый базовый стиль. Общую структуру меню параметризовать
   динамическими ресурсами; при смене структуры обеспечить корректную замену
   стиля. Не подставлять `DynamicResource` в `Style.BasedOn`, где он недопустим.
5. Не потерять поведение `WindowChrome`, drag, resize, maximize/restore
   и отступы развёрнутого окна. Внешнее скругление окна зависит также от ОС;
   `Border.CornerRadius` сам по себе не гарантирует форму системного окна.
   Проверку DWM/Windows 11 выполнить отдельно; нативный helper добавлять
   только при подтверждённой необходимости, зафиксировав файл в плане.
