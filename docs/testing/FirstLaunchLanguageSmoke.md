# 🌍 Ручная проверка языка при первом запуске

**Последняя сверка:** 2026-10-24. Реализация: `7d528dc`
(`fix(localization): apply system language on first launch`).

## 🎯 Ожидаемое поведение

Если `%APPDATA%/KID/settings.json` отсутствует, KID выбирает язык по исходной
`CultureInfo.CurrentUICulture`. Региональный формат чисел и дат Windows
сам по себе не определяет язык интерфейса.

- Русский и его региональные варианты, например `ru-RU` и `ru-BY`, дают `ru`.
- Украинский, например `uk-UA`, даёт `uk`.
- Английский, например `en-GB`, даёт `en`.
- Неподдерживаемый язык, например `sk-SK`, даёт резервный `en`.

Канонический код сохраняется в `UILanguage`. Отсутствие или повреждение
`DefaultWindowConfiguration.json` не меняет выбор языка первого запуска.
После успешной записи обновляется отметка языка в меню, даже если
`LocalizationService` уже использовал этот язык.

Сохранённый поддерживаемый выбор пользователя имеет приоритет при следующих
запусках. Восстановление некорректных существующих настроек — отдельный сценарий:
он по-прежнему использует default `ru` или `en` при аварийном каталоге.

## 👀 Сценарий

1. Закрыть все экземпляры KID. Если `settings.json` существует, сохранить его
   резервную копию под отдельным именем и убрать исходный файл на время проверки.
2. Запустить собранный KID с выбранной исходной UI-культурой. Использовать
   подготовленный профиль Windows с нужным языком либо временный загрузчик,
   задающий культуру только тестовому процессу до входа в приложение.
3. Проверить язык интерфейса и отметку выбранного языка в меню.
4. Проверить новый `%APPDATA%/KID/settings.json`: `UILanguage` должен содержать
   ожидаемый канонический код из перечня выше.
5. Закрыть тестовое окно. Если исходные настройки были сохранены, восстановить
   их из резервной копии; если файла до проверки не было, при необходимости
   удалить только созданный тестовый `settings.json`.

Сохранение вручную выбранного языка после обычного перезапуска проверяется
отдельно: выбрать другой язык в KID, закрыть приложение и запустить его без
подмены исходной UI-культуры. Этот сценарий не входит в результаты ниже.

## ✅ Подтверждённые результаты — 2026-10-24

Оба сценария выполнены на реальном Release-приложении. Временный
[.NET startup hook](https://github.com/dotnet/runtime/blob/main/docs/design/features/host-startup-hook.md)
задавал `CurrentUICulture` и `DefaultThreadCurrentUICulture` до входа в `Main`.
Исходная UI-культура процесса была `ru-RU`; язык Windows не менялся.
Загрузчик находился во временном каталоге и не добавлялся в проект.

- **`uk-UA → uk`.** Агент проверил завершение инициализации по журналу и
  сохранённое `"UILanguage": "uk"`. Пользователь подтвердил украинский интерфейс
  и отметку «Українська»: «Да, интерфейс и отметка правильные».
- **`sk-SK → en`.** Агент проверил завершение инициализации по журналу и
  сохранённое `"UILanguage": "en"`. Пользователь подтвердил английский интерфейс
  и отметку «English»: «Всё правильно, тестовое окно закрыто».
  После закрытия агент восстановил исходные украинские настройки; SHA-256
  восстановленного файла совпал с контрольной суммой резервной копии.

Это проверка приложения с другой исходной UI-культурой процесса. Установка
и переключение языковых пакетов Windows не проверялись. Обычный перезапуск,
переключение всех языков, диалоги файлов и остальная общая приёмка из § 11
[плана миграции](../agent/plans/NEUTRAL_LANGUAGE_CULTURES.plan.md) остаются отдельно.

## 🧪 Автоматизированное покрытие

В [WindowConfigurationServiceTests](../../KID.Tests/WindowConfigurationServiceTests.cs)
сценарии `FirstLaunch_*` проверяют поддерживаемые региональные варианты,
резервный английский, отсутствие или ошибку чтения стандартной конфигурации,
сохранение и уведомления меню. `Load_SavedLanguageOverridesSystemUiLanguage`
проверяет приоритет существующего выбора пользователя.

При обновлении этой документации сборка и тесты повторно не запускались.
