# 🪟 Ручная проверка самостоятельной библиотеки D005

Нужны Windows, .NET 10 SDK и аудиоустройство для шага звука. Проверка дополняет
автоматические тесты; результаты фиксируются отдельно. Используйте
[StandaloneDemo](../../samples/KID.Library.StandaloneDemo/README.md).

## 🎨 Собственное окно без консоли

```powershell
dotnet run --project samples/KID.Library.StandaloneDemo -c Release
```

1. Проверьте два круга на A и прямоугольник на B после A → B → A.
2. Нажмите Draw повторно: содержимое обоих полей сохраняется. Измените размер
   окна: обычная WPF-разметка работает без имён и Grid-индексов IDE.
3. Двигайте мышь над A, затем над B: MouseCanvas остаётся A. Нажмите клавиши
   при фокусе окна и проверьте обновление строки ввода.
4. Нажмите Tone: слышен тон 440 Hz около 0,5 секунды, UI остаётся отзывчивым.
   Повторите после рисования, затем закройте окно во время тона.
5. Запустите снова, нажмите STOP, затем закройте окно. Повторите быстрое
   закрытие при запуске и несколько запросов закрытия подряд. Не должно быть
   Dispatcher exception, зависания или незавершённого процесса.

## 🖥️ Необязательная консоль

```powershell
dotnet run --project samples/KID.Library.StandaloneDemo -c Release -- --with-console
```

1. Убедитесь, что появились TextBox и Read line; сообщение о рисовании приходит
   в TextBox. В режиме без флага консоль библиотеки отсутствует.
2. Нажмите Read line, введите имя и Enter: ответ появляется в TextBox.
3. Повторите Read line, введите несколько символов без Enter и нажмите STOP:
   ожидание завершается, частичный ввод не возвращается как готовая строка,
   приложение остаётся открытым.
4. Перезапустите и закройте окно при ожидающем Read line без ввода.
   UI должен обслуживать Dispatcher до завершения DisposeAsync.

## 🔄 Проверка интеграции IDE

Запустите KID.WPF.IDE. Проверьте обычное рисование, изменение размеров поля,
Console.WriteLine/ReadLine и звук; затем STOP во время цикла/ReadLine/звука,
повторный Run, ошибку компиляции, ошибку выполнения и закрытие IDE во время
выполнения. Новый Run возможен только после успешного cleanup. App-Window
не является частью этого сценария.

## 🧪 Автоматические дополнения

Release gate и пять режимов probe перечислены в
[журнале плана](../agent/plans/D005_KID.Library_STANDALONE_RESTORE.plan.md).
Для окна дополнительно выполните:

```powershell
dotnet run --project samples/KID.Library.StandaloneDemo -c Release -- --verify
dotnet run --project samples/KID.Library.StandaloneDemo -c Release --no-build -- --verify --with-console
```

Эти режимы автоматически проверяют Closing, ожидание задач и очистку **до**
shutdown Dispatcher, streams и повторное открытие. Они не подтверждают слышимость
звука, физический ввод или внешний вид. Частичный rollback и необратимый запрет
admission проверяют RuntimeSessionTests/RuntimeSessionFailureTests и
RuntimeSessionIntegrationTests в изолированных процессах.

Запишите дату, команды, exit codes, наблюдения по каждому ручному шагу и
непроверенные пункты. Не переносите результаты прошлых этапов в новый прогон.
