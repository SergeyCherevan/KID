# 📦 D012. Inno Setup для первого дистрибутива .KID

## 🎯 Контекст и задача

.KID — WPF IDE для Windows. Первый дистрибутив должен быть пригоден для домашнего
использования и развёртывания на школьных компьютерах. Выбор формата поставки
входит в открытые условия [аудита production readiness](../../work/audits/PRODUCTION_READINESS_AUDIT_2026-08-05.md).

## ✅ Решение и причины выбора

**Принято автором 2026-11-06: использовать Inno Setup для первого дистрибутива .KID.**
Основной формат — Windows-установщик EXE. MSIX не включается в первый канал поставки.

Причины выбора:

- Прямое распространение установщика подходит домашним компьютерам и школьным
  классам без обязательной зависимости от Store или MDM.
- Inno Setup поддерживает пользовательский и административный режимы установки,
  позволяя спроектировать поставку одному пользователю и на общий школьный ПК.
- Silent-параметры позволяют подготовить сценарий управляемого развёртывания;
  наличие Intune само по себе не требует выбора MSIX.
- Обычное размещение desktop-приложения позволяет начать с существующих путей
  данных .KID без добавления модели виртуализации AppData в scope первого канала.
- Один формат сокращает объём реализации и матрицу приёмки первого дистрибутива.

Это принятое решение об инструменте упаковки. Установщик и релизный процесс
ещё не реализованы; готовность дистрибутива этим решением не подтверждается.
[Поэтапный план дистрибутива](../../work/plans/DISTRIBUTION.plan.md) описывает
версионирование, publish, состав, подпись, installer, CI и release smoke;
предлагаемые параметры поставки в нём отделены от подтверждённых требований.

## 🏠 Предложения для проектирования установки

Следующие пункты обсуждены как рекомендуемый подход, но не являются отдельно
подтверждёнными параметрами поставки:

- Для дома — установка текущему пользователю без запроса административных прав.
- Для общего школьного ПК — установка администратором для всех пользователей;
  персональные настройки создаёт приложение при запуске каждого ученика.
- Один установщик с явно определёнными режимами и silent-командами для IT.
- Сохранение пользовательских файлов, настроек и recovery при обновлении и удалении.
- Начальное обновление запуском новой версии установщика; автообновление требует
  отдельного решения и реализации.

Режимы, пути, права и политика данных должны быть закреплены до реализации
и проверены на реальном установщике. Установщик, работающий от администратора
или SYSTEM, не должен подготавливать данные ученика в профиле этой учётной записи.

## 🧩 Границы решения и открытые вопросы

- **Runtime:** Inno Setup не определяет выбор framework-dependent или self-contained.
  Self-contained был предложен для удобства первого запуска, но требует отдельной
  реализации и приёмки. Текущий [KIDCompilationProfileProvider](../../../KID.WPF.IDE/Services/CompilationProfile/KIDCompilationProfileProvider.cs)
  явно отвергает такое размещение. Простое удаление запрета не сохраняет
  действующий состав references редактора и компилятора.
  [Проект поддержки self-contained](../../work/plans/SELF_CONTAINED_COMPILATION_PROFILE.plan.md)
  от 2026-11-07 описывает предлагаемые manifest/resolver и приёмку; реализация
  не начата и режим финального дистрибутива этим проектом не утверждён.
- **Поддерживаемая среда:** архитектуры, версии Windows, offline-режим и способ
  предоставления .NET ещё предстоит определить.
- **Версия и состав:** единый источник версии, SBOM, third-party notices,
  корневые LICENSE, SECURITY и CHANGELOG остаются отдельными задачами.
- **Подпись:** имя издателя, способ code signing, timestamp и проверка доверия
  ещё не выбраны. Выбор Inno Setup не является подтверждением подписи.
- **Сопровождение:** закреплённая версия инструмента, применимые условия его
  использования, обновление, downgrade и сосуществование режимов требуют решения.
- **Совместимость:** public API, assembly names и friend-доступ не меняются
  ради выбора установщика. Модель доверенного in-process выполнения сохраняется.

## ⚖️ Альтернатива MSIX и условия пересмотра

Вернуться к сравнению форматов следует при подтверждённой потребности в
обновлениях через Store/App Installer, package identity или конкретном школьном
канале, уже использующем MSIX. Intune поддерживает и Win32-развёртывание,
поэтому одного требования «работать с Intune» для смены решения недостаточно.

Перед добавлением MSIX потребуется проверить совместимость WPF/Roslyn,
доверие подписи, регистрацию для новых пользователей, миграцию данных между
каналами и сохранность recovery после удаления/повторной установки.
MSIX сам по себе не создаёт sandbox для учебного кода и не устраняет ограничение
self-contained в текущем compilation profile.
