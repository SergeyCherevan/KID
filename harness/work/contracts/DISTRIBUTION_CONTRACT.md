# 📦 Контракт первой поставки .KID

Состояние 2026-11-07: технический и продуктовый пакет ниже подтверждён автором
в этой задаче; правовые сведения, подпись и внешняя приёмка остаются открытыми.
Inno Setup утверждён в [D012](../../context/decisions/D012_InnoSetup.md).
Открытые пункты ограничивают релиз, но не разработку технической возможности.

## Подтверждено

- Inno Setup; локальные Conventional Commits, без push и внешней публикации.
- Сохраняются API, identity сборок, singleton profile и доверенное in-process выполнение.
- Self-contained реализуется независимо от окончательного выбора runtime поставки.
- Кандидат идентифицируется SHA; после приёмки его байты не пересоздаются.

## Подтверждено автором 2026-11-07

- SCD, Release/win-x64, файловый layout; single-file/trimming/AOT/ReadyToRun выключены.
- Windows 11 x64; конкретные builds требуют VM-приёмки. Windows 10 не объявляется
  поддерживаемой только потому, что используется рабочим компьютером.
- Полный offline payload. Runtime обслуживается новым выпуском .KID.
- Per-user: LocalAppData/Programs/KID; all-users: Program Files/KID, admin/SYSTEM.
  Отдельная регистрация scopes, запрет молчаливого перехода между ними.
- Silent install/uninstall с логом; обновление новым installer; downgrade запрещён.
  При работающей IDE установка отказывает; принудительное закрытие запрещено.
- Пользовательские исходники, settings и recovery сохраняются при upgrade/uninstall.
  Installer не создаёт данные ученика; их создаёт приложение при запуске ученика.
- Первый выпуск 0.1.0, кандидаты 0.1.0-rc.N; FileVersion 0.1.0.N;
  AssemblyVersion 1.0.0.0 сохраняет существующую идентичность KID.Library.
  Четвёртый компонент FileVersion монотонен, включая переход rc→stable;
  для stable убрать suffix, сохранив более высокий числовой installer revision.
- Course/примеры включены после проверки прав; symbols отдельным архивом.
- Microsoft SBOM Tool, SPDX 2.2; версию инструмента закрепить после проверки.
- Scan production transitive NuGet + runtime: High/Critical и недоступный источник
  блокируют выпуск; исключения требуют явного решения с причиной и сроком.

## Подтверждено автором 2026-11-16

- `.KID IDE` (`KID.WPF.IDE/`), `KID.Library` (`KID.Library/`) и `course` (`course/`)
  лицензируются независимо друг от друга по Apache-2.0.
- Правообладатель всех трёх частей: Сергей Черевань; copyright notice — 2026.
- Каждая часть содержит собственные LICENSE и NOTICE. Корневой LICENSE содержит
  тот же стандартный текст для совместной поставки. При отдельной поставке
  сохраняются лицензионные документы соответствующей части.
- Сторонние лицензии, notices review и проверка прав на ресурсы остаются
  самостоятельными обязательствами; выбор Apache-2.0 не подтверждает их приёмку.

## Контакт безопасности и подпись: решение автора 2026-11-16

- Приватные сообщения об уязвимостях: `CherevanSergeyKharkov@gmail.com`.
  Автор разрешил публично указать этот адрес в SECURITY.md; документ ещё не создан.
- Издатель: Сергей Черевань как частное лицо. Выбран локальный самоподписанный
  сертификат для Authenticode: бесплатно, без KYC и внешней проверки личности.
- Для первой поставки требование публично доверенной цепочки заменяется проверкой
  подписи с явно выбранным сертификатом/ключом. Это не даёт автоматического
  доверия чужой Windows и не обещает отсутствия предупреждений SmartScreen.
- Передача подлинного открытого ключа/отпечатка пользователям, точный certificate
  subject, срок действия, резервирование ключа и timestamp требуют проработки.
  Закрытый ключ не включается в репозиторий, payload или логи.
- Это решение о целевой схеме, а не её реализация: текущий Signed path явно
  отвергает self-signed сертификаты. Нужны отдельная адаптация и приёмка;
  создание сертификата и изменение доверенных хранилищ здесь не выполняются.

## Канал распространения: решение автора 2026-11-16

- Официальные установщики .KID распространяются через
  [GitHub Releases репозитория SergeyCherevan/KID](https://github.com/SergeyCherevan/KID/releases).
- Выбор площадки не является публикацией: release/tag/assets в этой задаче
  не создаются, push не выполняется. Готовность кандидата и его приёмка
  проверяются отдельно.

## Хранение кандидатов и поставщик SBOM: решения автора 2026-11-16

- Отклонённые или заменённые кандидаты выпуска (rc) и их диагностические архивы
  хранятся 180 дней с момента отклонения или замены; `retentionDays = 180`.
  К действующему кандидату и принятым выпускам это правило не применяется;
  хранение принятых выпусков определяется отдельно.
- Срок хранения выбран, но автоматическая очистка не реализована и удаление
  файлов этим решением не выполняется.
- Поставщик всего пакета .KID для SBOM: `Sergey Cherevan`, частное лицо.
  Поставщики и авторские сведения сторонних компонентов сохраняются отдельно.
- Базовый namespace SBOM: `https://github.com/SergeyCherevan/KID/sbom`
  (`namespaceUri`, подтверждено автором 2026-11-16). Он передаётся генератору
  как база; уникальный namespace конкретного документа формирует инструмент.
  Доступная веб-страница по этому адресу не требуется.
- Supplier и namespace определены; генерация, полнота и успешная приёмка
  финального SBOM остаются отдельными задачами.

## Решения и доступ, без которых выпуск запрещён

- Проверенные права на сторонние учебные материалы и ресурсы; лицензия и правообладатель собственных трёх частей определены выше.
- SECURITY.md с выбранным контактом, генерация и приёмка финального SBOM;
  реализация политики хранения кандидатов и подготовка комплекта для GitHub Releases.
- Реализация выбранной self-signed схемы: ожидаемый certificate subject/ключ,
  передача доверия пользователям, политика timestamp и доступ к ключу вне
  репозитория/логов. Платные услуги и KYC исключены решением автора.
- Чистые Windows VM без SDK/shared runtime и ручная приёмка установленного кандидата.
- Внешний CI run на соответствующем commit (без самостоятельного push).
